## 1. 全局约定（双端必须一致，承袭 M1）

1. **时区**：唯一使用**设备本地时区**（`remindAt` 为设备本地时区的绝对时刻，切换时区不改写已存值，仅展示随本地时区解释）。触发点计算同样基于设备本地时区，规避时区漂移（R-U5）。
2. **触发点绝对时间**：所有触发点为**绝对本地时刻**（`Date`），存于系统通知中心 / WorkManager，不依赖相对倒计时漂移。
3. **taskId 标识前缀**：所有平台通知请求标识（iOS `request.identifier` / Android Work `tag`）均以 `taskId.uuidString` 为前缀，格式见 §2.4，以保证完成时精确批量取消。
4. **重复间隔固定 10 分钟**：重复点间距严格为 10 分钟（PRD R-E6 / P0-2），由触发点生成算法保证，不以系统默认重复间隔替代。
5. **`until` 扫描上界**：默认 `REMINDER_SCAN_HORIZON_DAYS = 7`（可配置），`tasksWithPendingReminders(until:)` 的入参 = `now + 7天`，见 §5。
6. **单一事实源**：复用 M1 的 `Task.remindAt` / `leadMinutes` / `repeatCount` 字段与 `tasksWithPendingReminders` 方法；**不新增任何 Task 字段**，不建独立 `Reminder` 表（v1.1 再议）。

## 2. 触发点生成规则（核心）

### 2.1 规则定义

给定 `Task.remindAt = T`、`leadMinutes = L`（默认 10）、`repeatCount = R`（默认 3，`0` = 关闭重复），生成触发点集合：

| 类型 | 生成条件 | 触发时刻 | 标识后缀（见 §2.4） |
|------|----------|----------|---------------------|
| 提前（lead） | `L > 0` | `T − L 分钟` | `__lead` |
| 到点（at） | 总是 | `T` | `__at` |
| 重复 i（repeat） | `R > 0` 且 `i = 1..R` | `T + i × 10 分钟` | `__rep{i}` |

- `L = 0`：**不生成**提前点（用户关闭提前提醒）。
- `R = 0`：**不生成**任何重复点（用户关闭重复；AC-11）。
- 默认（`L=10, R=3`）完整集合：`T−10`、`T`、`T+10`、`T+20`、`T+30` 共 5 个点（对应 AC-7 / AC-8）。

> 重复点**全部预先生成**（与到点、提前点一同登记），不在 Work/通知内做运行时计数自增——计数由独立触发点表达，更确定、易取消、易补偿。

### 2.2 平台无关生成算法（伪代码，双端同源）

```text
// 输入：一条 Task（含 remindAt/leadMinutes/repeatCount）
// 输出：有序触发点列表（按 fireAt 升序），每个点含 taskId + 类型 + 绝对时刻
FUNCTION buildTriggerPoints(task) -> List<TriggerPoint>:
    IF task.remindAt IS NULL:
        RETURN []                         // 未设提醒，无触发点
    T  = task.remindAt                    // 绝对本地时刻
    L  = task.leadMinutes                 // 默认 10
    R  = task.repeatCount                 // 默认 3，0=关闭
    points = []

    IF L > 0:
        points.append( TriggerPoint(task.id, kind=LEAD,    fireAt = T - L * 60_000 ms) )
    points.append( TriggerPoint(task.id, kind=AT,      fireAt = T) )
    IF R > 0:
        FOR i IN 1..R:
            points.append( TriggerPoint(task.id, kind=REPEAT(i), fireAt = T + i * (10 * 60_000 ms)) )

    SORT points BY fireAt ASC
    RETURN points
```

### 2.3 触发点数据结构（双端一致语义）

```
TriggerPoint:
    taskId : UUID            // 归属任务
    kind   : enum { LEAD, AT, REPEAT }   // REPEAT 携带 index:Int
    fireAt : Date            // 绝对触发时刻（设备本地时区）
    identifier : String      // 由 taskId + 后缀派生，见 §2.4
```

### 2.4 标识（identifier）派生规则（双端一致）

| 触发点 | iOS `request.identifier` | Android Work `tag` |
|--------|--------------------------|--------------------|
| 提前 | `"\(taskId)__lead"` | `"\(taskId)__lead"` |
| 到点 | `"\(taskId)__at"` | `"\(taskId)__at"` |
| 重复 i | `"\(taskId)__rep\(i)"` | `"\(taskId)__rep\(i)"` |
| 推迟（snooze） | `"\(taskId)__snooze"` | `"\(taskId)__snooze"` |

- **取消语义**：完成时只需移除以上由 `taskId` 派生的全部标识即可（iOS `removePendingNotificationRequests(withIdentifiers:)`、Android `cancelAllWorkByTag(taskId)` 配合统一 tag = `taskId`）。snooze 标识同样以 `taskId` 为前缀，故一并被取消。
- **推迟标识唯一性**：snooze 仅允许一个有效实例（新的推迟覆盖旧的：`cancel(taskId)` 先清掉旧 `__snooze`，再建新 `__snooze`），避免叠加。

### 2.5 「到点已完成时后续重复点不响」的判断时机（关键）

判定分两层，**双端统一语义**：

1. **主路径（完成时主动取消）**：`TaskRepository.markDone(_:at:)` 成功后，**立即调用 `ReminderScheduler.cancel(for: taskId)`**，移除该任务全部未触发的 pending 通知（含提前/重复点）。这是满足 AC-9 / R-E7 的主机制——任务一旦完成，重复点根本不会触发。
2. **触发时兜底（通知层查 isDone）**：
   - **Android（完全实现）**：每个重复点是一个独立 `OneTimeWorkRequest`，Work 在触发**执行时**先查 `TaskRepository.isDone(taskId)`：未完成 → 发通知；已完成 → **不发**并结束（见 §4.3）。这真正实现了「触发时查 isDone」的抗竞态兜底（例如 markDone 与排程因异常未对齐时）。
   - **iOS（边界说明）**：系统级 pending `UNNotificationRequest` **无法在触发时刻被 App 条件性抑制**（通知内容在登记时即定稿，App 沙盒无法在触发瞬间查询 Core Data 阻止展示）。因此 iOS 的等价保证来自主路径的「完成即取消」。为降低残留体验问题：
     - 重复通知的 Action「标记完成」对已完成任务为**幂等**（再次 markDone 为 no-op）；
     - 通知标题/正文可声明任务内容，用户点开即知已完成；
     - 仍由 App 内「待完成 / 错过的提醒」列表兜底（R-X3 / AC-10）。
   - **结论**：Android 端由 Work 执行时查 `isDone` 完整实现要求；iOS 端以「完成即取消 + 幂等 Action + in-app 兜底」等价满足，属 iOS 平台能力边界，按架构「失败兜底优先」原则处理，不阻塞上线。

> **时间点澄清**：「到点已完成时后续重复点不响」的判定，正常情况由 markDone 时的 cancel 保证；极端竞态由 Android 的触发时 isDone 查保证。文档明确该时机，避免开发误以为 iOS 也能在触发瞬间拦截。

## 3. iOS 方案（UNUserNotificationCenter）

### 3.1 接口与实现（可编译级签名）

```swift
import Foundation
import UserNotifications

// 与 M1 对齐的纯领域模型（已在 M1 定义，此处仅引用）
// struct TaskDTO: Identifiable { let id: UUID; var remindAt: Date?; var leadMinutes: Int; var repeatCount: Int; ... }

enum TriggerKind: String {
    case lead
    case at
    case repeatN
    case snooze
}

struct TriggerPoint {
    let taskId: UUID
    let kind: TriggerKind
    let repeatIndex: Int      // 仅 repeatN 使用，其余为 0
    let fireAt: Date

    var identifier: String {
        switch kind {
        case .lead:    return "\(taskId.uuidString)__lead"
        case .at:      return "\(taskId.uuidString)__at"
        case .repeatN: return "\(taskId.uuidString)__rep\(repeatIndex)"
        case .snooze:  return "\(taskId.uuidString)__snooze"
        }
    }
}

/// 通知层协议（沿用 M1 §7.2，此处补全实现约束）
protocol ReminderScheduler {
    func schedule(for task: TaskDTO)
    func cancel(for taskId: UUID)
    func rescheduleAllPending()
}

final class NativeReminderScheduler: ReminderScheduler {

    static let categoryIdentifier = "REMINDER_CATEGORY"
    static let actionComplete = "action_complete"   // 标记完成
    static let actionSnooze   = "action_snooze"     // 推迟 10 分钟

    private let center = UNUserNotificationCenter.current()
    private let repository: TaskRepository           // M1 已实现

    init(repository: TaskRepository) { self.repository = repository }

    // MARK: - 触发点生成（平台无关算法的 Swift 表达）
    private func buildTriggerPoints(_ task: TaskDTO) -> [TriggerPoint] {
        guard let t = task.remindAt else { return [] }
        var pts: [TriggerPoint] = []
        if task.leadMinutes > 0 {
            pts.append(.init(taskId: task.id, kind: .lead, repeatIndex: 0,
                             fireAt: t.addingTimeInterval(-Double(task.leadMinutes) * 60)))
        }
        pts.append(.init(taskId: task.id, kind: .at, repeatIndex: 0, fireAt: t))
        if task.repeatCount > 0 {
            for i in 1...task.repeatCount {
                pts.append(.init(taskId: task.id, kind: .repeatN, repeatIndex: i,
                                 fireAt: t.addingTimeInterval(Double(i) * 10 * 60)))
            }
        }
        return pts.sorted { $0.fireAt < $1.fireAt }
    }

    // MARK: - 编排日期组件（绝对本地时间，避开时区漂移）
    private func dateComponents(_ date: Date) -> DateComponents {
        Calendar.current.dateComponents([.year, .month, .day, .hour, .minute, .second], from: date)
    }

    // MARK: - schedule
    func schedule(for task: TaskDTO) {
        // 先清旧，再登记（幂等：同 identifier 会覆盖）
        cancel(for: task.id)
        let content = makeContent(task)
        for pt in buildTriggerPoints(task) {
            var c = content
            c.userInfo = ["taskId": task.id.uuidString, "kind": pt.kind.rawValue, "repeatIndex": pt.repeatIndex]
            let trigger = UNCalendarNotificationTrigger(dateMatching: dateComponents(pt.fireAt), repeats: false)
            let req = UNNotificationRequest(identifier: pt.identifier, content: c, trigger: trigger)
            center.add(req)
        }
    }

    private func makeContent(_ task: TaskDTO) -> UNMutableNotificationContent {
        let c = UNMutableNotificationContent()
        c.title = "待办提醒"
        c.body = task.title
        c.categoryIdentifier = Self.categoryIdentifier
        c.sound = .default
        return c
    }

    // MARK: - cancel
    func cancel(for taskId: UUID) {
        var ids = ["\(taskId.uuidString)__lead",
                   "\(taskId.uuidString)__at",
                   "\(taskId.uuidString)__snooze"]
        for i in 1...maxRepeatUpperBound { ids.append("\(taskId.uuidString)__rep\(i)") }
        center.removePendingNotificationRequests(withIdentifiers: ids)
    }
    // maxRepeatUpperBound：取运行期该任务 repeatCount 上限；安全起见用常量 REPEAT_MAX = 3（与 P0-2 对齐）
    private let maxRepeatUpperBound = 3

    // MARK: - 推迟 10 分钟
    func snooze(_ taskId: UUID) {
        let id = "\(taskId.uuidString)__snooze"
        center.removePendingNotificationRequests(withIdentifiers: [id])
        let fire = Date().addingTimeInterval(10 * 60)
        let req = UNNotificationRequest(identifier: id,
                  content: makeContentForSnooze(taskId),
                  trigger: UNCalendarNotificationTrigger(dateMatching: dateComponents(fire), repeats: false))
        center.add(req)
    }

    // MARK: - rescheduleAllPending（启动/前台补偿）
    func rescheduleAllPending() {
        let horizon = Date().addingTimeInterval(REMINDER_SCAN_HORIZON_DAYS * 24 * 3600)
        let tasks: [TaskDTO]
        do { tasks = try repository.tasksWithPendingReminders(until: horizon) }
        catch { return }
        for t in tasks { schedule(for: t) }   // schedule 内含 cancel，天然幂等重建
    }
}

// 常量（可配置，与 Android 一致）
let REMINDER_SCAN_HORIZON_DAYS: TimeInterval = 7
```

### 3.2 通知交互（UNNotificationCategory + Action）

```swift
// App 启动早期（如 @main 的 init）注册分类
func registerReminderCategory() {
    let complete = UNNotificationAction(identifier: NativeReminderScheduler.actionComplete,
                                        title: "标记完成", options: [.authenticationRequired])
    let snooze   = UNNotificationAction(identifier: NativeReminderScheduler.actionSnooze,
                                        title: "推迟10分钟", options: [])
    let category = UNNotificationCategory(identifier: NativeReminderScheduler.categoryIdentifier,
                                          actions: [complete, snooze],
                                          intentIdentifiers: [], options: [])
    UNUserNotificationCenter.current().setNotificationCategories([category])
}

// UNUserNotificationCenterDelegate（AppDelegate / SwiftUI App）
func userNotificationCenter(_ center: UNUserNotificationCenter,
                            didReceive response: UNNotificationResponse,
                            withCompletionHandler completion: @escaping () -> Void) {
    let info = response.notification.request.content.userInfo
    guard let taskIdStr = info["taskId"] as? String,
          let taskId = UUID(uuidString: taskIdStr) else { completion(); return }
    switch response.actionIdentifier {
    case NativeReminderScheduler.actionComplete:
        try? repository.markDone(taskId, at: Date())   // 同时应由 markDone 内部调用 cancel(for:) 移除后续点
    case NativeReminderScheduler.actionSnooze:
        scheduler.snooze(taskId)
    default: break
    }
    completion()
}
```

> **markDone 与 cancel 的联动（关键）**：`TaskRepository.markDone` 实现中（或 ViewModel 调用链）在置完成后必须调用 `ReminderScheduler.cancel(for: taskId)`，确保 AC-9 / R-E7 完成即取消后续。建议将此联动封装在领域层 `completeTaskUseCase`，避免散落遗漏（M1 验收 §⑥ 跟进项 7 明确要求）。

### 3.3 启动 / 前台补偿触发点

| 触发时机 | 调用 |
|----------|------|
| App 冷启动 / 热启动 | `application(_:didFinishLaunchingWithOptions:)` 或 SwiftUI `.onAppear` 首屏后 |
| 进入前台 | `applicationWillEnterForeground` / `sceneDidBecomeActive` |

两者均调用 `scheduler.rescheduleAllPending()`，重建未来 7 天内 pending（补偿杀进程 / 重启 / 系统清理丢失，§5）。

### 3.4 免打扰（iOS 专注模式）——平台边界

- iOS **专注模式 / 勿扰为系统级拦截，App 无法绕过**（架构 §5.2）。
- **引导文案**（设置页 / 首次提醒说明）：「若开启「专注模式」或「勿扰」，本 App 提醒可能被静音。可在「设置 → 专注」中将本 App 加入允许通知列表；未完成待办也会在 App 内『待完成』列表展示，不会漏看。」
- **兜底**：App 内「待完成」列表（进行中且有 `remindAt` 在过去/未来）持续可见；被系统吞掉的通知对应待办仍可在列表看到（R-X3 / AC-10）。

## 4. Android 方案（WorkManager + NotificationManager）

### 4.1 接口与实现（可编译级签名）

```kotlin
import androidx.work.*
import java.util.Date
import java.util.UUID
import java.util.concurrent.TimeUnit

// 触发点类型
enum class TriggerKind { LEAD, AT, REPEAT, SNOOZE }

data class TriggerPoint(
    val taskId: UUID,
    val kind: TriggerKind,
    val repeatIndex: Int,   // 仅 REPEAT 使用
    val fireAt: Date
) {
    val identifier: String
        get() = when (kind) {
            TriggerKind.LEAD    -> "${taskId}__lead"
            TriggerKind.AT      -> "${taskId}__at"
            TriggerKind.REPEAT  -> "${taskId}__rep$repeatIndex"
            TriggerKind.SNOOZE  -> "${taskId}__snooze"
        }
    // WorkManager 用 taskId 作唯一 tag，便于批量取消
    val tag: String get() = taskId.toString()
}

interface ReminderScheduler {
    fun schedule(task: Task)
    fun cancel(taskId: UUID)
    fun rescheduleAllPending()
}

class WorkManagerReminderScheduler(
    private val context: Context,
    private val workManager: WorkManager,
    private val repository: TaskRepository   // M1 已实现
) : ReminderScheduler {

    companion object {
        const val CHANNEL_ID = "channel_reminder"
        const val ACTION_COMPLETE = "action_complete"
        const val ACTION_SNOOZE = "action_snooze"
        const val EXTRA_TASK_ID = "extra_task_id"
        const val REMINDER_SCAN_HORIZON_DAYS = 7
    }

    // 触发点生成（平台无关算法的 Kotlin 表达）
    private fun buildTriggerPoints(task: Task): List<TriggerPoint> {
        val t = task.remindAt ?: return emptyList()
        val pts = mutableListOf<TriggerPoint>()
        if (task.leadMinutes > 0) {
            pts += TriggerPoint(task.id, TriggerKind.LEAD, 0,
                Date(t.time - task.leadMinutes * 60_000L))
        }
        pts += TriggerPoint(task.id, TriggerKind.AT, 0, t)
        if (task.repeatCount > 0) {
            for (i in 1..task.repeatCount) {
                pts += TriggerPoint(task.id, TriggerKind.REPEAT, i,
                    Date(t.time + i * 10 * 60_000L))
            }
        }
        return pts.sortedBy { it.fireAt.time }
    }

    override fun schedule(task: Task) {
        cancel(task.id)   // 先清旧，再登记（幂等）
        val now = System.currentTimeMillis()
        for (pt in buildTriggerPoints(task)) {
            val delay = (pt.fireAt.time - now).coerceAtLeast(0L)
            val req = OneTimeWorkRequestBuilder<ReminderWorker>()
                .setInitialDelay(delay, TimeUnit.MILLISECONDS)
                .addTag(pt.tag)                       // = taskId，便于 cancelAllWorkByTag
                .setInputData(workDataOf(
                    EXTRA_TASK_ID to pt.taskId.toString(),
                    "kind" to pt.kind.name,
                    "repeatIndex" to pt.repeatIndex
                ))
                .build()
            workManager.enqueue(req)
        }
    }

    override fun cancel(taskId: UUID) {
        workManager.cancelAllWorkByTag(taskId.toString())
    }

    fun snooze(taskId: UUID) {
        workManager.cancelAllWorkByTag(taskId.toString())  // 清旧 snooze（同 tag）
        val delay = 10 * 60_000L
        val req = OneTimeWorkRequestBuilder<ReminderWorker>()
            .setInitialDelay(delay, TimeUnit.MILLISECONDS)
            .addTag(taskId.toString())
            .setInputData(workDataOf(
                EXTRA_TASK_ID to taskId.toString(),
                "kind" to TriggerKind.SNOOZE.name,
                "repeatIndex" to 0
            ))
            .build()
        workManager.enqueue(req)
    }

    override fun rescheduleAllPending() {
        val horizon = Date(System.currentTimeMillis() + REMINDER_SCAN_HORIZON_DAYS * 24 * 3600_000L)
        // 注意：仅对「未完成且有 remindAt」且在窗口内的重建；tasksWithPendingReminders 已按语义过滤
        runBlocking {
            val tasks = repository.tasksWithPendingReminders(horizon)
            tasks.forEach { schedule(it) }   // schedule 内含 cancel，幂等重建
        }
    }
}
```

### 4.2 Work 执行体（触发时查 isDone —— 实现 §2.5 兜底）

```kotlin
class ReminderWorker(
    private val context: Context,
    params: WorkerParameters
) : CoroutineWorker(context, params) {

    @Inject lateinit var repository: TaskRepository   // 通过 Hilt/手动注入
    @Inject lateinit var notificationHelper: ReminderNotificationHelper

    override suspend fun doWork(): Result {
        val taskIdStr = inputData.getString(EXTRA_TASK_ID) ?: return Result.failure()
        val taskId = runCatching { UUID.fromString(taskIdStr) }.getOrElse { return Result.failure() }
        val kind = inputData.getString("kind") ?: return Result.failure()

        // —— 触发时查 isDone：到点已完成，则重复点不响（§2.5）——
        val task = repository.get(taskId) ?: return Result.failure()
        if (task.isDone) return Result.success()   // 已完成：不发通知，结束

        notificationHelper.showReminder(task, kind)
        return Result.success()
    }
}
```

> `repository.get(id)` 为 M1 已有 `TaskRepository` 的便捷读取（若未暴露，可在 M2 由 `todayTasks()` 过滤或新增 `get(id:)`；本规格不强制新增，开发可选用合适读取路径）。**关键不变式**：每个重复点 Work 在真正发通知前 MUST 校验 `isDone`，这是「到点已完成后续重复不响」的 Android 端完整保证。

### 4.3 通知渠道与展示

```kotlin
object ReminderNotificationHelper {

    fun ensureChannel(context: Context) {
        val mgr = context.getSystemService(NotificationManager::class.java)
        val channel = NotificationChannel(
            CHANNEL_ID, "待办提醒",
            NotificationManager.IMPORTANCE_HIGH   // 重要 + 声音/振动
        ).apply {
            enableVibration(true)
            setSound(RingtoneManager.getDefaultUri(RingtoneManager.TYPE_NOTIFICATION),
                     AudioAttributes.Builder()
                         .setUsage(AudioAttributes.USAGE_NOTIFICATION).build())
            // DND 绕过见 §4.5
        }
        mgr.createNotificationChannel(channel)
    }

    fun showReminder(task: Task, kind: String) {
        val mgr = context.getSystemService(NotificationManager::class.java)
        val intent = Intent(context, MainActivity::class.java).apply {
            flags = Intent.FLAG_ACTIVITY_SINGLE_TOP
            putExtra(EXTRA_TASK_ID, task.id.toString())
        }
        val pi = PendingIntent.getActivity(context, task.id.hashCode(),
            intent, PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE)

        val completeAction = NotificationCompat.Action.Builder(
            android.R.drawable.ic_menu_save, "标记完成", completePendingIntent(task.id)).build()
        val snoozeAction = NotificationCompat.Action.Builder(
            android.R.drawable.ic_menu_recent_history, "推迟10分钟", snoozePendingIntent(task.id)).build()

        val builder = NotificationCompat.Builder(context, CHANNEL_ID)
            .setSmallIcon(R.drawable.ic_reminder)
            .setContentTitle("待办提醒")
            .setContentText(task.title)
            .setContentIntent(pi)
            .setAutoCancel(true)
            .addAction(completeAction)
            .addAction(snoozeAction)
        mgr.notify(task.id.hashCode(), builder.build())
    }
}
```

> Action 的 `PendingIntent` 复用广播 `ReminderActionReceiver`：收到 `ACTION_COMPLETE` → 调 `repository.markDone(id, Date())` 并 `scheduler.cancel(id)`；收到 `ACTION_SNOOZE` → `scheduler.snooze(id)`。

### 4.4 启动 / 网络恢复补偿触发点

| 触发时机 | 调用 |
|----------|------|
| Application 冷启动 | `Application.onCreate` 之后（或首屏 `ViewModel` 初始化） |
| 进入前台 | `Activity.onResume` / `ProcessLifecycleOwner` 前台回调 |
| 网络恢复（辅助） | `WorkManager` 自身具备网络约束能力；本地提醒本不强依赖网络，此处仅作与 iOS 对齐的补偿名目，`rescheduleAllPending` 行为一致 |

两次均调用 `scheduler.rescheduleAllPending()`，重建未来 7 天 pending（补偿 Doze / 重启 / 系统清理丢失，§5）。
**WorkManager 重启韧性**：`OneTimeWorkRequest` 由 WorkManager 内部持久化，设备重启后经 `BOOT_COMPLETED` 接收器自动重新排程，**本身即可跨重启保留**；`rescheduleAllPending` 作为数据库驱动下的二次修复（如跨日窗口、标记完成与排程未能对齐时的重建）机制。

### 4.5 免打扰（Android DND）

- 重要提醒用 `Notification.setBypassDnd(true)` 需 `ACCESS_NOTIFICATION_POLICY` 权限（Android 6.0+）。
- **权限请求流程**：
  ```kotlin
  val nm = getSystemService(NotificationManager::class.java)
  if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.M && !nm.isNotificationPolicyAccessGranted) {
      // 引导用户去设置开启「绕过勿扰」
      startActivity(Intent(Settings.ACTION_NOTIFICATION_POLICY_ACCESS_SETTINGS))
  }
  ```
- **引导文案**（设置页 / 首次提醒说明）：「如需在「勿扰」模式下仍响铃提醒，请在系统设置中允许本 App「绕过勿扰」。未授权时提醒仅显示在通知栏、不响铃；未完成待办也会在 App 内『待完成』列表展示。」
- **未授权兜底**：仅通知栏展示、不响铃；App 内列表兜底（R-X3 / AC-10）。
- **通知被禁检测**（R-S4 / AC-20）：用 `NotificationManagerCompat.from(context).areNotificationsEnabled()` 回调判断（无轮询），首页常驻提示「提醒可能不送达」。

## 5. `until` 扫描上界与跨日

1. **扫描上界**：`tasksWithPendingReminders(until:)` 的 `until` 取 `now + REMINDER_SCAN_HORIZON_DAYS × 24h`，`REMINDER_SCAN_HORIZON_DAYS = 7`（双端常量一致，可配置）。语义沿用 M1 §5.3：未完成 + 有 `remindAt` + `remindAt ∈ [now, until]`。
2. **跨日覆盖**：`remindAt` 为绝对本地时刻，跨自然日仍按设定时刻触发（R-U4）。若提醒落在未来多日，只要 App 在 7 天窗口内被启动/进入前台，`rescheduleAllPending` 即会重建该 pending。
3. **跨日唤醒取舍（v1 边界）**：**v1 不做后台常驻唤醒**。若用户连续多日不打开 App，超出 7 天窗口的远期提醒无法在设定时刻触发（系统层限制）。取舍与体验边界：
   - 这是「纯本地、零登录、轻量」定位下的有意取舍，避免后台常驻带来的耗电/被系统强杀风险；
   - 兜底：被吞/未达的待办在用户下次打开 App 时于首页「错过的提醒」区补列并标记「提醒未达」（R-X3 / AC-10）；
   - 常用提醒（当日/次日）均在 7 天窗口内，绝大多数场景被覆盖；
   - 若后续需更强保证，v1.1 可评估后台 fetch / 精确闹钟（仍受 Doze 限制），不在本 M2 范围。
4. **时区**：切换时区不改写已存 `remindAt`（不漂移），触发点按新本地时区解释（R-U5 / AC-27③）。`UNCalendarNotificationTrigger` 与 `WorkManager.setInitialDelay` 均基于绝对时刻计算，天然符合。

## 6. 与 M1 接口对齐（无新增字段、无独立表）

1. **复用 M1 字段**：`Task.remindAt` / `leadMinutes` / `repeatCount`（类型与默认值见 M1 §2.1：`Date?` / `Int` 默认 10 / `Int` 默认 3），M2 **不新增任何 Task 字段**。
2. **复用 M1 方法**：`TaskRepository.tasksWithPendingReminders(until:)`（M1 §5.3 已冻结语义）为补偿扫描唯一入口；`markDone(_:at:)` 为完成联动 cancel 的触发点。
3. **不建独立 `Reminder` 表**：M2 触发点完全由 `ReminderScheduler` 在**内存 + 系统通知中心 / WorkManager** 管理，不落独立表（架构 §6.1 的 `Reminder` 实体推迟到 v1.1）。这样避免 M1 数据层返工，符合 M1 验收 §⑥ 跟进项 7「数据层零返工」。
4. **改期 / 取消完成的对齐**：
   - 改期（R-E11 / AC-28 `T→T'`）：UI 调 `repository.update(task)` 写新 `remindAt` 后，调用 `scheduler.schedule(task)`（内含 `cancel` 清旧点 + 按新 T 重建），不重复通知。
   - 取消完成（R-E10 / AC-26 后半）：`repository.update`（置 `isDone=false, doneAt=nil`）后，调用 `scheduler.schedule(task)` 恢复其提醒排程（提前/到点/重复），因 `isDone` 已回退，触发时 Work 会正常发通知。
5. **埋点调用点（仅标注，不写上报）**：`reminder_set`（设/改提醒时）、`reminder_trigger`/`reminder_shown`（Work/通知实际展示时）、`reminder_complete`/`reminder_dismiss`（Action 回调时）在对应位置留调用点，供开发接入 PRD §11 埋点。

## 8. 双端对照表（速查）

| 维度 | iOS（`NativeReminderScheduler`） | Android（`WorkManagerReminderScheduler`） |
|------|----------------------------------|------------------------------------------|
| 调度原语 | `UNNotificationRequest` × N | `OneTimeWorkRequest` × N |
| 触发器 | `UNCalendarNotificationTrigger`（绝对本地时间） | `setInitialDelay` 到绝对时刻 |
| 取消 | `removePendingNotificationRequests(withIdentifiers:)` 前缀标识 | `cancelAllWorkByTag(taskId)` |
| 完成时取消 | `cancel(for:)` 移除未触发点（主路径） | `cancel(taskId)` 移除未触发 Work（主路径） |
| 触发时查 isDone | 系统限制不可拦截；靠完成即取消 + 幂等 Action + 列表兜底 | Work `doWork` 先查 `isDone`，已完成则**不发**（完整兜底） |
| 重复点表达 | 预生成 N 个独立 request | 预生成 N 个独立 Work |
| 交互 Action | `UNNotificationCategory`（标记完成/推迟10分） | 通知 `Action`（标记完成/推迟10分） |
| 启动/前台补偿 | `rescheduleAllPending()` 扫未来7天 | `rescheduleAllPending()` 扫未来7天 |
| 重启韧性 | 系统通知中心保留 pending；启动重建 | WorkManager 内部持久化自动跨重启；启动重建为二次修复 |
| DND | 系统级不可绕过；引导 + 列表兜底 | `setBypassDnd(true)` 需 `ACCESS_NOTIFICATION_POLICY` 授权；未授权仅栏显 |
| 通知被禁检测 | `authorizationStatus` 回调 | `areNotificationsEnabled()` 回调 |
