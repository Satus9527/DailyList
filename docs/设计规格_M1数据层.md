## 1. 全局约定（双端必须一致）

1. **时区**：唯一使用**设备本地时区**（PRD R-U5）。已存的绝对时间（`remindAt`/`doneAt`/`updatedAt`）为设备本地时区的绝对时刻，切换时区**不改写**已存值，仅展示随本地时区解释。
2. **`date` 字段格式**：以 `String` 形式存为 `"yyyy-MM-dd"`（本地时区当日），**不使用 Date 类型存储「日」**，避免时区/日历漂移（R-U4）。应用层可将其解析为 `Date` 仅用于展示。
3. **UUID**：id 统一为 UUID v4，跨端以规范字符串（小写、含连字符）互通。
4. **枚举持久化**：统一以 `String` 原始值（rawValue / name）落库，**禁止用整数 ordinal**，避免两端/版本间错位。
5. **title 长度上限**：500 字符（PRD R-X5 / AC-29）。写入前由上层截断并提示，存储层以 `NOT NULL` 约束、长度由上层保证。
6. **同步预埋**：所有写操作更新 `updatedAt`；`syncState` 默认 `local`，M1 不消费，v1.1 同步引擎再将变更翻为 `dirty`。
7. **事务**：单条新增/完成/编辑均单事务提交，保证杀进程不丢（F6 / R-U1）。

## 5. Repository 接口精确签名（平台无关协议）

> 仅定义存储契约；实现 `LocalTaskRepository`（iOS Core Data / Android Room）。所有方法在主线程外（后台上下文）执行，返回 Swift 用 `@MainActor` 桥接刷新 UI。

### 5.1 Swift 协议

```swift
import Foundation

protocol TaskRepository {
    /// 当天的全部待办，按「进行中在上、已完成置底；同日按 sortOrder 升序」排序
    func todayTasks() throws -> [Task]

    /// 新增一条（id/updatedAt 由仓库补全或用调用方给定）
    func add(_ task: Task) throws

    /// 全量更新一条（含 isDone/title/categoryId/priority/remindAt/leadMinutes/repeatCount/sortOrder 等）
    func update(_ task: Task) throws

    /// 标记完成：isDone=true, doneAt=at, updatedAt=now
    func markDone(_ id: UUID, at date: Date) throws

    /// 删除一条（级联删除其 Tag 关联）
    func delete(_ id: UUID) throws

    /// 重排：按 ids 给定顺序，将每条 sortOrder 设为该下标；仅影响传入的当日待办
    func reorder(ids: [UUID]) throws

    /// 扫描未完成且有 remindAt，且 remindAt ∈ [now, until] 的待办（支撑 F3 重启/跨日补偿）
    /// - Parameter until: 扫描上界（绝对时刻）。now 取调用时刻。
    func tasksWithPendingReminders(until date: Date) throws -> [Task]
}
```

> 注：`markDone` 为便捷方法；「取消完成」(PRD AC-26) 通过 `update(_:)` 将 `isDone=false`、`doneAt=nil` 实现，无需新增接口。

### 5.2 Kotlin 接口（suspend，配合 Flow 可选）

```kotlin
import java.util.Date
import java.util.UUID

interface TaskRepository {
    /** 当天全部待办，排序见 §5.1 */
    suspend fun todayTasks(): List<Task>

    /** 新增一条 */
    suspend fun add(task: Task)

    /** 全量更新一条 */
    suspend fun update(task: Task)

    /** 标记完成 */
    suspend fun markDone(id: UUID, at: Date)

    /** 删除一条（级联删 Tag 关联） */
    suspend fun delete(id: UUID)

    /** 重排：ids 顺序即新 sortOrder */
    suspend fun reorder(ids: List<UUID>)

    /** 扫描 remindAt ∈ [now, until] 且未完成的待办 */
    suspend fun tasksWithPendingReminders(until: Date): List<Task>
}
```

### 5.3 `tasksWithPendingReminders` 精确扫描语义（双端一致）

匹配**全部**以下条件，返回按 `remindAt` 升序：

1. `isDone == false`
2. `remindAt != nil`（已设置提醒）
3. `remindAt >= now`（`now` = 调用该方法时的当前设备时刻）
4. `remindAt <= until`（入参上界，绝对时刻）

> `until` 由 F3 调用方传入（例如「未来 7 天」），用于限制一次性加载量；扫描下界固定为调用时刻 `now`，避免重复返回已过期项。跨日场景由通知层在 App 启动/重排时调用本方法覆盖。

### 7.3 DAO 精确 @Query（含全部 7 方法）

```kotlin
@Dao
interface TaskDao {
    // F1/F5/F6：当天列表，进行中在上、已完成置底，同组按 sortOrder 升序
    @Query("""
        SELECT * FROM task
        WHERE date = :today
        ORDER BY is_done ASC, sort_order ASC
    """)
    suspend fun todayTasks(today: String): List<TaskEntity>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(task: TaskEntity)

    @Update
    suspend fun update(task: TaskEntity)

    // F5：标记完成
    @Query("""
        UPDATE task
        SET is_done = 1, done_at = :at, updated_at = :updatedAt
        WHERE id = :id
    """)
    suspend fun markDone(id: String, at: Date, updatedAt: Date)

    @Delete
    suspend fun delete(task: TaskEntity)

    @Query("DELETE FROM task WHERE id = :id")
    suspend fun deleteById(id: String)

    // F5：拖拽重排（@Transaction 保证原子）
    @Transaction
    suspend fun reorder(orders: List<IdOrder>) {
        orders.forEach { (id, sortOrder) ->
            @Query("UPDATE task SET sort_order = :sortOrder WHERE id = :id")
            updateSortOrder(id, sortOrder)
        }
    }
    @Query("UPDATE task SET sort_order = :sortOrder WHERE id = :id")
    suspend fun updateSortOrder(id: String, sortOrder: Int)

    // F3 扫描：未完成 + 有 remindAt + remindAt ∈ [now, until]
    @Query("""
        SELECT * FROM task
        WHERE is_done = 0
          AND remind_at IS NOT NULL
          AND remind_at >= :now
          AND remind_at <= :until
        ORDER BY remind_at ASC
    """)
    suspend fun tasksWithPendingReminders(now: Date, until: Date): List<TaskEntity>
}

data class IdOrder(val id: String, val sortOrder: Int)
```

> 说明：`reorder` 在实现上以 `@Transaction` 包一组 `UPDATE`；也可改为单条 `@Query("UPDATE task SET sort_order = :idx WHERE id = :id")` 循环。DAO 仅暴露存储原语，`LocalTaskRepository` 负责把 `Task`（领域模型）与 `TaskEntity` 互转、`today` 取本地 `yyyy-MM-dd`、为 `markDone` 注入 `updatedAt = Date()`。

## 9. 迁移与版本策略

| 项目 | iOS（Core Data） | Android（Room） |
|------|------------------|-----------------|
| 当前版本 | `NSManagedObjectModel` 版本 `1`（标识符 `"M1"`） | `@Database(version = 1)` |
| v1 升级策略 | 版本 1 为初始；v1 内无迁移 | `Room.databaseBuilder(...).fallbackToDestructiveMigration()` |
| 是否可接受 destructive | v1 用户无历史数据或极少；destructive 可接受 | v1 无旧版本用户数据，destructive 可接受 |
| 说明 | 首次发版即 v1；后续若改模型走 Mapping Model / 轻量迁移 | `fallbackToDestructiveMigration()` 在 version 升到 2 时丢弃旧表重建；v1.1 引入新表（Reminder/RecurringTemplate 等）时应**改为显式 `Migration`** 以保留既有待办 |
| 占位 schema 版本字段 | 模型版本号 + `CoreDataMetadata` 可记 `schemaVersion` | `RoomDatabase` 内 `version`，可额外在 `user_version` pragma 记录 |

> **决策**：M1（v1）允许 destructive 迁移（用户尚处初期、数据可重建）；自 v1.1 起任何涉及既有表的变更必须提供显式 `Migration`，禁止 destructive 丢数据。存储层需在打开库时打印当前 schema version 便于排查。

## 10. 存储损坏兜底（P0-3 v1 = 方案 B）实现规格

### 10.1 捕获点（双端一致）

1. **DB 打开/创建**：初始化 Core Data 栈 / `Room.databaseBuilder().build()` 的 try 块。
2. **迁移执行**：`fallbackToDestructiveMigration` 之前若迁移逻辑抛错（Room 显式 Migration 路径）；Core Data 轻量迁移失败。
3. **首启种子（Category 预设）写入**：若种子事务失败也按损坏处理。

### 10.2 最小日志内容（仅本地、不联网）

日志写入本地文件（沙盒 `Application Support/logs/db_error.log` 或系统日志），**不含任何账号/网络上报**，至少含：

```
[DB_ERROR] timestamp=<ISO8601 本地时间>
event=<open_failed | migration_failed | corrupt_detected>
dbPath=<库的绝对沙盒路径>
errorType=<异常类/SQLite 错误码>
message=<异常本地描述，可含 SQLITE_CORRUPT 等>
action=<rebuilt_empty_db>
```

### 10.3 重建空库触发条件（保证不崩溃）

- 打开/迁移抛 `NSError(SQLite ...)` / `SQLiteException` / `IllegalStateException`（如 `Room` 打开失败）→ 捕获 → 记日志 → **删除损坏库文件 → 重建空库 → 重新执行首启种子（Category 预设）**。
- 重建后仍失败（极端，如磁盘满）→ 仍**捕获并不抛出到 UI 线程**，降级为内存态（仅本次会话可用，提示「数据可能受损」），App 不崩溃（对应 PRD AC-19 / R-X2）。
- UI 层在重建后弹出一次性提示「本地数据可能已损坏，已重置为空，历史记录可能丢失」，不阻塞记录流程。

### 10.4 不崩溃保证

- 所有 DB 初始化代码在 `do/try-catch`（Swift）/`try/catch`（Kotlin）内；异常**绝不**向上抛到 `AppDelegate`/`Application.onCreate` 之外。
- 仓库方法返回 `Result`/`throws`，调用方对失败做降级而非崩溃。
