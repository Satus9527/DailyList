## 二、逐条 AC 判定与证据

### AC-2（实时转写）— 逻辑通过 / 需真机验证录音质量
- iOS：`NativeASRController.handleRecognitionResult`（`ASRController.swift:200-204`）将 partial 经 `DispatchQueue.main.async` 回调；`TodayTaskViewModel.startVoice` 的 `onPartial`（`TodayTaskViewModel.swift:225`）写入 `voicePartialText`；`TodayView.swift:75` 实时渲染。
- Android：`onPartialResults`（`NativeASRController.kt:94-102`）→ `TodayViewModel.startVoice` 的 `onPartial`（`TodayViewModel.kt:111`）→ `TodayScreen.kt:173` 渲染；空时显示「聆听中…」。
- 结论：展示链路完整。**真机验证方法**：授权麦克风后口述，观察输入框是否实时出现转写文字（受原生 ASR 识别率与方言影响，见 PRD 风险「中文/方言识别率有限」）。

### AC-3（标点/停顿自动拆分）— 部分通过
- 标点集 `{。！？；}`、停顿阈值 1200ms、不含「、」与换行：双端 `VoiceTaskSplitter` 严格消费 JSON（见第三节专项），逻辑正确。
- 「继续监听」：iOS 单识别任务持续喂缓冲；Android `onResults` 后 `beginListening()`（`NativeASRController.kt:113`）形成听写循环。✓
- **分歧点（需产品/架构确认）**：PRD R-E2 原文「用户停止录音时未达句末标点的尾句**并入最后一条**待办」；而 `设计规格_M3语音层.md §2.3/§3.4/§5.2` 将尾句实现为「作为单独一条或并入最后一条」，代码采用「单独成条」（`ASRController.swift:330-333` 尾句再 `onFinal`→splitter 生成新条）。即实现遵循 M3 设计规格，但与 PRD R-E2 字面不一致。**建议**：产品确认尾句语义以哪一版为准（并入 vs 单独成条），并同步修正 PRD 或设计规格。
- **粒度说明（不阻塞）**：iOS 在持续听期间 `result.isFinal` 仅在 `stop()` 时为真，标点切分实际发生在「长停顿边界/停止」提交整段后由 splitter 切分，并非每个标点实时成条；这与规格 §3.4 一致，但测试人员须知「遇标点自动生成」的粒度是「句段边界级」而非「逐字符级」。

### AC-4（空/静音不落库）— 通过
- iOS `where !seg.isEmpty`（`VoiceTaskSplitter.swift:25`）+ `flushFinalBoundary` 空判定（`ASRController.swift:292`）；Android `filter { it.isNotBlank() }`（`VoiceTaskSplitter.kt:35`）+ `onResults` 空判定（`NativeASRController.kt:108`）。纯标点文本（如「。」）不产生待办（splitter 丢弃尾标点后段空）。✓

### AC-5（合并/拆分持久化）— iOS 部分通过 / Android 不通过
- iOS：`TaskMergeSplitUseCase.swift:25-62` 实现 `merge`/`split`，复用 M1 `repository.update/add/delete`；`split` 保留 `source`、断点标点归属前段（`TaskMergeSplitUseCase.swift:46-48`），符合规格 §7；VM 暴露 `merge`/`split`（`TodayTaskViewModel.swift:288-297`）。**但全仓无 UI 入口触发**（无长按手势选中相邻/断点），用户无法实际操作 → 列表更新与重启保持无法经 UI 验证。
- Android：**未实现** `TaskMergeSplitUseCase`（全局检索仅 iOS 有）；`domain/voice/` 仅 `VoiceTaskSplitter.kt`。即 Android 端合并/拆分的领域逻辑与 UI 入口均缺失。
- 结论：AC-5 **不通过（Android）/ 部分通过（iOS，逻辑+持久化具备但缺 UI 触发）**。**真机验证方法**：长按照期待办→合并相邻/在指定字符拆分→检查列表即时更新→杀进程重启→确认保持。需开发补齐 Android 用例与双端 UI 入口。

### AC-6（降级+文字兜底）— 通过（逻辑）
- iOS：`handleDegrade`（`TodayTaskViewModel.swift:278-285`）置 `voiceAvailable=false`+`isVoiceActive=false`+Toast「语音暂不可用，请改用文字输入」；`TodayView.swift:51` 麦克风按钮 `disabled(!voiceAvailable && !isVoiceActive)`，文字输入框始终可用。
- Android：`onVoiceDegraded`（`TodayViewModel.kt:167-170`）置 `VoiceState.Degraded`；`TodayScreen.kt:96-100` 弹 Snackbar；`TodayScreen.kt:163` 按钮 `enabled` 仅 Idle/Listening（Degraded 自动置灰）；下方 `OutlinedTextField` 始终可用。
- 触发面：权限拒、能力不可用、`ERROR_NETWORK` 重试仍失败、`AUDIOFOCUS_LOSS`、识别失败（见第三节）。✓

### AC-21（权限引导）— 部分通过
- 双端均在进语音入口发起授权（iOS `requestPermission` 弹系统框；Android `recordAudioLauncher.launch(RECORD_AUDIO)`），拒绝后给文字引导。
- **缺口**：永久拒绝后无「去系统设置重新授权」深链（AC-22 同因）。建议补设置页/深链（见跟进项）。

### AC-22（设置页权限状态+重授权）— 不通过
- 双端均无「设置」页面（`ios` 仅 `TodayView`+`ReminderSettingView`；`android` 仅 `ReminderSettingSheet.kt`）。PRD §9 与规格 §8 要求的「权限状态可见 + 跳转系统设置 + 语音输入开关」未落地。
- 说明：M3 设计规格 §0 将 P0-1 隐私标注为「仅文案/策略声明」，但 §8 明确「设置页提供语音输入开关」「权限状态可见并可跳系统设置重授权（AC-22）」。属范围确认问题，建议产品/架构拍板是否 M3 必须含设置页，否则降级为 M3.1/后置。

### AC-29（超长截断）— 部分通过（语音路径无提示）
- 语音 splitter 双端均截断至 500 字（iOS `VoiceTaskSplitter.swift:27`；Android `VoiceTaskSplitter.kt:38`），与 F1 一致。
- **缺口**：截断后未向用户提示（F1 `addFromInput` 有「内容超过 500 字，已截断」提示，语音路径没有）。规格 §9.6 要求「截断并提示（R-X5/AC-29）」。属一般缺陷（见 D3）。

## 三、专项核对

### 3.1 自动拆分消费 JSON（P0-4 防漂移）
**结论：通过（静态）。**

1. **唯一来源**：双端均解析 JSON，无任何拆分常量硬编码。
   - `shared/asr_split_config.json`、`ios/DailyPlan/Resources/asr_split_config.json`、`android/app/src/main/assets/asr_split_config.json` 三者内容一致：`splitPunctuation=["。","！","？","；"]`、`splitPauseThresholdMs=1200`、`includeEnumerationComma=false`、`includeNewline=false`。
   - iOS：`ASRSplitConfig.loadFromBundle()`（`ASRSplitConfig.swift:18-22`）→ `VoiceTaskSplitter` 取 `config.splitPunctuation`（`VoiceTaskSplitter.swift:19`）→ `punctuationSet`；阈值经 `ASRController.swift:184`→`SilentPauseMonitor(thresholdMs: splitConfig.splitPauseThresholdMs)`（`SilentPauseMonitor.swift:22`）。
   - Android：`ASRSplitConfig.load(context)`（`ASRSplitConfig.kt:23-27`）→ `punctuationSet=config.splitPunctuation.toSet()`（`VoiceTaskSplitter.kt:24`）；`pauseThresholdMs=config?.splitPauseThresholdMs?.toLong()`（`NativeASRController.kt:39`）。
   - 全仓检索 `。！？；` / `1200` 仅出现在注释，无字面量常量（Grep 已确认）→ **P0-4 防漂移满足**。
2. **标点集/停顿/顿号/换行**语义：
   - 仅 `splitPunctuation` 触发切分，段尾标点丢弃（`VoiceTaskSplitter.swift:41-45`、`VoiceTaskSplitter.kt:61-65`）。✓
   - 长停顿 >1.2s：iOS `SilentPauseMonitor` 用 RMS 累计 ≥ `thresholdMs`（`SilentPauseMonitor.swift:38`）；Android `onRmsChanged` 累计 `paused >= pauseThresholdMs`（`NativeASRController.kt:143-148`）。阈值均来自配置。✓
   - 「、」不切：`includeEnumerationComma=false` → 顿号并入（`VoiceTaskSplitter.swift:46-47`、`VoiceTaskSplitter.kt:66`）。✓
   - 换行不切：`includeNewline=false` → 换行并入（`VoiceTaskSplitter.swift:48-49`、`VoiceTaskSplitter.kt:67`）。✓
3. **用户手动「落一条」优先**：
   - iOS `commitManualSegment`（`TodayTaskViewModel.swift:251-258`）取 `asr.bufferedText` 直接 `commitFinalSegment` 并 `clearBuffer`；按钮 `TodayView.swift:80`。
   - Android `commitManual`（`TodayViewModel.kt:134-140`）取 `getBufferedText()`，按钮 `TodayScreen.kt:178`。✓ 符合 R-E2 用户优先。
4. **缺失兜底**：iOS 配置缺失回退空集→`voiceAvailable=false`（`DailyPlanApp.swift:28-34`、`TodayTaskViewModel.swift:48`）；Android `config=null`→`voiceSplitter=null`→`Unavailable`（`TodayViewModel.kt:104-107`）。均无硬编码常量，符合 P0-4 精神。
5. **需真机验证**：iOS 资源 `asr_split_config.json` 须确认已加入 Xcode Build Phases「Copy Bundle Resources」（仓库无 `.xcodeproj`，无法静态确认）；Android `assets/` 通常随打包，待真机/打包验证加载非空。
