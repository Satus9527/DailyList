## 1. 背景

用户需要一款"能真正用起来"的每日计划工具。核心诉求是**极低门槛地记录当天待办**，录入同时覆盖**语音 + 文字**两种形态，降低"打开就要打字"的阻力。

主流待办工具（滴答清单、Todoist、Microsoft To Do、Google Keep）功能完整但偏"管理"，对"只看今天、随手记"的轻量场景偏重，且大多**强制或默认需要账号登录**才能使用核心能力，造成首启流失。

本产品的差异化定位为：**纯本地零登录 + 语音优先的当日记录流**，避开"先注册再使用"的门槛，用最低操作成本完成"记录 → 提醒 → 完成"的当日闭环。

---

## 2. 目标

### 2.1 产品目标（v1）

- **G1 低门槛记录**：用户 **30 秒内**完成"今天要做什么"的记录（语音 / 文字均可）。
- **G2 不漏事**：关键待办能**准时提醒**，到点前预警、到点强提醒、未完成重复兜底。
- **G3 轻量组织**：用**分类 / 优先级 / 标签**做轻量组织，而非复杂项目管理。
- **G4 当日可见进度**：v1 显示「今日完成 X / 共 Y」轻量进度，形成完成正反馈。

### 2.2 业务目标

- 以"轻量语音记录"为差异化切入，**验证日活（DAU）与次日留存**。
- 验证"记录 → 提醒 → 完成"核心闭环是否成立，作为后续 v1.1（循环/统计）投入的依据。
- 不追求功能全面，先验证"当日记录"这一单点价值能否留住用户。

## 3. 目标用户与核心场景

| 维度 | 内容 |
|------|------|
| 目标用户 | 通用个人效率人群（不限定职场 / 学生） |
| 核心痛点 | 想记待办时手不方便打字；待办散落各处；到点忘记做 |
| 平台形态 | iOS + Android 原生 App（v1 不做小程序 / Web） |
| 数据存储 | 纯本地存储，无账号登录（换机 / 卸载数据不保留，v1 简化） |

### 3.1 用户故事（覆盖核心场景）

> 采用「作为 <角色>，我希望 <能力>，以便 <价值>」格式；每条标注对应功能与版本。

- **US-1（通勤口述）**：作为通勤中的用户，我希望**按住/点按语音键口述今日待办**，系统自动按停顿拆成多条，以便手不方便时也能 30 秒记完今天的事。（F2，v1）
- **US-2（随手打字）**：作为工作中的用户，我希望**直接输入文字新增一条待办**，以便临时起意时快速落一条。（F1，v1）
- **US-3（到点不漏）**：作为健忘的用户，我希望**给关键待办设提醒时间**，系统提前 10 分钟、到点、未完成时重复提醒，以便不漏事。（F3，v1）
- **US-4（轻量归类）**：作为爱整理的用户，我希望**给待办分分类、标优先级、打标签**，以便在当天视图里一眼分清轻重缓急。（F4，v1）
- **US-5（完成正反馈）**：作为追求成就感的用户，我希望**勾选完成、并看到"今日完成 X / 共 Y"**，以便获得当日完成的掌控感。（F5，v1）
- **US-6（误识别可救）**：作为被语音切错的用户，我希望**手动合并 / 拆分已生成的待办**，以便语音自动拆分出错时能即时纠正。（F2/F5，v1）
- **US-7（重启不丢）**：作为长期使用用户，我希望**杀进程 / 重启后待办完整恢复**，以便本地数据可靠。（F6，v1）
- **US-8（权限被拒也能用）**：作为拒绝麦克风权限的用户，我希望**系统引导我用文字继续记录**，以便权限缺失不阻断核心流程。（权限，v1）
- **US-9（历史回顾，v1.1）**：作为复盘型用户，我希望**查看历史日计划与完成率**，以便了解自己的执行趋势。（F7，v1.1）
- **US-10（周模板循环，v1.1）**：作为有规律日程的用户，我希望**按周模板自动生成每日待办、可单独改某天、漏做的能改时间补生成**，以便固定事务零成本。（F8，v1.1）

## 5. 需求描述（EARS 原则）

> EARS 五模式：Ubiquitous（始终）/ Event-driven（当…时）/ State-driven（当处于…状态时）/ Unwanted（若…则，异常）/ Optional（若启用…特性时）。
> 每条需求标注编号、模式、版本。口径与计算见 §10。

### 5.1 Ubiquitous（始终成立）

- **R-U1（v1）**：系统应始终将用户当日待办持久化于本地存储，App 重启后**完整恢复**当日列表（含完成态、顺序、分类、优先级、标签、提醒设置）。
- **R-U2（v1）**：系统应始终允许用户在无网络环境下记录、查看、完成、编辑待办（纯本地零依赖）。
- **R-U3（v1）**：系统应始终在首页展示「今日完成 X / 共 Y」进度（X、Y 口径见 §10）。
- **R-U4（v1）**：系统应始终按待办「创建自然日」（以设备本地时区计）归属当日清单；提醒跨自然日仍按设定时刻触发，并在触发日归入「当天进行中」展示。
- **R-U5（v1）**：系统应始终以设备本地时区为唯一时区；用户切换时区时不改写已设绝对提醒时间（不漂移）。

### 5.2 Event-driven（事件触发）

- **R-E1（v1）**：当用户点击语音按钮并开始说话时，系统应持续监听并将语音实时转写为文字（边说边显）。
- **R-E2（v1）**：当检测到拆分信号时，系统应将已识别文本拆分为一条独立待办并加入当日列表，随后继续监听下一条。拆分信号以**句末标点（。！？；）为主**、**长停顿（>1.2s）为辅**；**不按「、」切分**（「、」视为同一待办内列举，并入当前条）；用户停止录音时未达句末标点的尾句**并入最后一条**待办（若当前无条则单独成条）。换行视为停顿信号之一。
- **R-E3（v1）**：当用户通过文字输入框提交一条待办时，系统应将其加入当日列表并清空输入框。
- **R-E4（v1）**：当用户为某条待办设定提醒时间到达时，系统应推送本地通知（到点提醒）。
- **R-E5（v1）**：当提醒时间提前 10 分钟到达（默认）时，系统应推送提前提醒通知。
- **R-E6（v1）**：当到点提醒已触发且用户未标记完成时，系统应每 10 分钟重复推送，最多 3 次（或直到完成/关闭）。
- **R-E7（v1）**：当用户标记某待办完成时，系统应取消其所有未触发的后续提醒并停止重复。
- **R-E8（v1）**：当语音自动拆分出的待办被用户合并/拆分时，系统应更新列表且合并/拆分结果被持久化。
- **R-E9（v1）**：当用户首次启动 App 且未授权麦克风时，系统应在语音入口处展示权限引导。
- **R-E10（v1）**：当用户将某已完成待办「取消完成」时，系统应将其进度 X-1 并移回进行中列表；若该待办仍有未触发的提醒排程，则恢复其提醒（含提前/到点/重复）。
- **R-E11（v1）**：当用户将某待办提醒时间由 T 改为 T' 时，系统应取消旧触发点（含提前/重复排程）并按 T' 重新登记，不发送重复通知（对应测试 TC-R3-06）。

### 5.3 State-driven（状态驱动）

- **R-S1（v1）**：当某待办处于"已完成"状态时，系统应将其从进行中列表**置底**并展示完成态（如删除线 / 勾选）。
- **R-S2（v1）**：当系统处于"录音中"状态时，系统应显示录音态（波形 / 计时 / 停止按钮）并禁用文字提交干扰。
- **R-S3（v1）**：当待办设有提醒且处于未来时间，系统应在该条展示提醒时钟标识与设定时间。
- **R-S4（v1·异常态）**：系统应通过系统授权状态回调判断「通知被禁」（iOS `authorizationStatus` / Android `areNotificationsEnabled`），无轮询；当检测到通知被禁时，首页应以常驻提示告知用户"提醒可能不送达"（不阻塞记录）。「勿扰」态检测见 P2（§13.3 #12）。

### 5.4 Unwanted（异常 / 反向需求）

- **R-X1（v1）**：若语音识别服务不可用（系统 ASR 异常 / 离线不支持）或授权被拒，则系统应提示用户改用文字输入，并**保持记录流程可用**。
- **R-X2（v1）**：若本地存储写入失败 / 文件损坏，则系统应：① 记录异常日志（含损坏标记与时间戳），保留仍可操作的内存态，**不崩溃**；② v1 **不强制恢复**（不尝试自动重建数据），仅提示用户数据可能受损。轻量本地快照恢复（自动回滚至最近可用快照）作为 v1.1 增强（方案 C，见 §14）。
- **R-X3（v1）**：若同一条待办的提醒因系统限制未能在设定时刻展示（如 App 被杀且系统未调度），则系统应在用户下次打开 App 时于首页"错过的提醒"区补列该待办，标记为"提醒未达"。
- **R-X4（v1）**：若语音转写内容为空 / 静音过长，则系统应自动结束本条识别且不生成空待办。
- **R-X5（v1）**：若用户输入待办文本长度超过 500 字上限，则系统应截断至 500 字并提示用户（对应测试 TC-T1-06）。

### 5.5 Optional（可选特性）

- **R-O1（v1）**：当用户输入标签时，系统应支持从已有标签自动联想补全；标签录入时去重/归一（忽略大小写、首尾空格、全角半角）；用户可跳过，非必填。
- **R-O2（v1）**：当用户未设分类时，系统应默认归入「其他」；优先级默认「中」且不强制展示标识；筛选支持单维与组合（可选能力，不影响核心记录）。
- **R-O3（v1.1）**：当启用"周模板循环"时，系统应按模板每日自动生成待办，并支持单天覆盖与漏做补生成（F8，v1.1）。
- **R-O4（v1.1）**：当启用"历史统计"时，系统应展示历史日计划与完成率趋势（F7，v1.1）。

## 6. 流程说明

### 6.1 记录流程（文字）
```
用户打开 App
  → 首页展示「今日」清单与进度 X/Y
  → 用户在输入框键入文字 → 回车/点「+」
  → [Event R-E3] 生成一条"进行中"待办，落当天，清空输入
  → （可选）点分类/优先级/标签补全 → 持久化
```
边界：空内容提交 → 不生成；超长文本（≥ 500 字，默认上限 500 字）→ 截断至 500 字并提示用户（见 R-X5 / AC-29）。

### 6.2 语音录入流程
```
用户点语音按钮
  → [Event R-E1] 检测麦克风权限
       ├─ 已授权 → 开始持续听，边说边显转写
       └─ 未授权 → [Event R-E9] 弹权限引导（去设置 / 改用文字）
  → 说话中：遇停顿/标点 → [Event R-E2] 拆分生成一条待办，继续听
  → 空/静音过长 → [Unwanted R-X4] 结束本条，不生成空待办
  → 用户点「停止」→ 收尾转写，未达停顿的尾句并入最后一条或单独成条
  → 拆分不准 → [Event R-E8] 用户手动合并/拆分 → 持久化
  → ASR 不可用 → [Unwanted R-X1] 提示改用文字，记录流程不中断
```
容错：识别错误支持单条编辑（F5）；拆分错误支持合并/拆分（F2/F5）。

### 6.3 提醒流程
```
用户给待办设时间 T
  → 持久化提醒设置（T、提前量、重复开关）
  → 系统登记本地通知：
       ├─ T-10min → [Event R-E5] 提前提醒
       ├─ T       → [Event R-E4] 到点提醒
       └─ 未完成   → [Event R-E6] 每 10min 重复，最多 3 次
  → 用户标记完成 → [Event R-E7] 取消后续提醒
  → 用户手动关闭重复 → 仅保留提前+到点
  → 通知被禁/勿扰/杀进程 → [State R-S4 / Unwanted R-X3] 首页"错过的提醒"补列
```
默认策略：提前 10 分 + 到点 + 每 10 分重复最多 3 次；单条可调/关闭（**已定，见 §14**）。

### 6.4 循环待办生成 / 补生成流程（v1.1，仅描述不实现）
```
用户配置周模板（周一~周日各自待办集合）
  → 每日 00:00（或首启）按当日星期自动生成待办
  → 单天可覆盖：改/删/增该天项，不影响模板
  → 漏做检测：当日结束（如 23:59）仍有未完成项
       → 用户可将其"改到其他时间" → 生成带新时间的待办
       → 或"补生成"到指定未来日（沿用原内容）
```
> v1.1 范围，v1 不实现、不预留 UI 入口。

## 7. 交互说明

### 7.1 页面 / 模块

| 模块 | 平台 | 关键内容 |
|------|------|---------|
| 首页（今日） | 移动端主屏 | 顶部进度「完成 X / 共 Y」；当日待办列表（进行中在上、已完成置底）；底部文字输入框 + 语音按钮；分类/优先级快速筛选 |
| 待办编辑 | 弹层/新页 | 内容、分类、优先级、标签、提醒时间、重复开关 |
| 语音录入 | 覆盖层 | 录音态（波形/计时/停止）、实时转写、已生成条数、合并/拆分入口、权限引导兜底 |
| 设置 | 新页 | 权限状态（麦克风/通知）、隐私说明、默认提醒策略展示（v1 仅展示，v1.1 可改） |
| 错过的提醒（v1 异常区） | 首页区块 | 列出提醒未达的待办，标记"提醒未达" |

### 7.2 关键交互

- **新增**：文字回车即增；语音点按即录。两条路径产物一致（均为"进行中"待办）。
- **完成**：勾选 → 置底 + 完成态 + 进度 +1 + 取消后续提醒。
- **排序**：拖拽调整当日顺序，持久化。
- **语音拆分纠正**：长按某条 → 合并（选相邻）/ 拆分（按标点或手动断点）。
- **提醒设置**：编辑页选时间；默认策略自动套用，可改提前量 / 关重复。

### 7.3 状态清单

| 状态 | 含义 | 表现 |
|------|------|------|
| 进行中 | 未完成的当日待办 | 列表上部，无删除线 |
| 已完成 | 用户勾选完成 | 置底、删除线/勾选、进度计数 |
| 录音中 | 语音录入进行 | 覆盖层录音态，禁用文字干扰 |
| 已设提醒 | 未来时间待办 | 时钟标识 + 时间 |
| 提醒未达 | 系统未能在设定时刻展示 | 首页"错过的提醒"区标记 |
| 权限缺失 | 麦克风/通知未授权 | 入口引导提示，不阻断记录 |

## 8. 数据指标

### 8.1 北极星指标

- **NS（北极星）：当日闭环用户数** = 当天满足「新增记录 ≥ 1 条待办 **且** 当天完成 ≥ 1 条待办」的去重用户数。
- 选择理由：直接度量产品核心承诺——"低门槛记录且当天真用起来"，比单纯 DAU 更能反映价值交付。

### 8.2 留存与转化

| 指标 | 定义（口径见 §10） | 目标（待确认基线后定） |
|------|------------------|----------------------|
| 次日留存 | 首日有记录的用户的次日仍启动并记录的占比 | 待确认 |
| 7 日留存 | 同上口径扩至 7 日 | 待确认 |
| 记录转化率 | 当日启动 App 的用户中，记录 ≥ 1 条待办的占比 | 待确认 |
| 语音使用率 | 当日记录待办中，由语音产生的条数占比（或语音功能用户占比） | 待确认 |
| 提醒触达率 | 已设定提醒的待办中，通知成功展示的比例 | 待确认 |
| 提醒完成率 | 已设定提醒的待办中，最终完成的比例 | 待确认 |
| 当日完成率 | 当日完成 X / 共 Y（X÷Y） | 待确认 |

> 所有目标数值需负责人/数据在灰度后基于真实基线确认，PRD 不臆断。

## 9. 权限与隐私规则

| 权限 | 用途 | 引导策略 | 拒绝后行为 |
|------|------|---------|-----------|
| 麦克风 | 语音录入（F2） | 首次进语音入口弹系统授权；附"语音经系统 ASR 在设备端或联网转写，弱网/离线可能上传音频至系统厂商（Apple/Google），可在设置关闭语音输入"说明 | [Unwanted R-X1] 提示改用文字，记录流程可用 |

## 10. 数据口径定义（单一事实来源）

| 术语 | 口径 |
|------|------|
| 当日 / 今天 | 以设备本地时区的自然日 00:00–23:59；换日以本地 0 点切分 |
| 新增记录 | 用户通过文字或语音成功生成一条"进行中"待办的计数（空/静音不计入，R-X4） |
| 完成 | 用户主动勾选完成（含语音拆分后再完成的条） |
| X / Y（进度） | X = 当日已完成条数；Y = 当日总条数（含已完成 + 进行中），不含已删除 |
| 提醒触达 | 系统本地通知成功投递至通知中心并被系统记为展示（以系统回调为准） |
| 提醒未达 | 到点后未收到系统展示回调，且用户后续打开 App 时仍在"错过的提醒"区 |
| 语音条数 | 语音自动拆分 + 用户手动合并/拆分后最终计入列表的条数 |
| DAU | 当日至少启动一次 App 的去重设备数 |
| 闭环用户 | 满足 NS 定义的用户 |

## 12. 验收标准（每条可测）

> 每条可测：给定输入/前置，期望可观测输出。标注对应需求与版本。

### 12.1 记录（文字 / 语音）
- **AC-1（F1/R-E3）**：输入非空文字并提交 → 列表新增一条"进行中"待办，输入框清空。
- **AC-2（F2/R-E1）**：授权麦克风后点语音并说话 → 实时转写文本出现。
- **AC-3（F2/R-E2）**：说话中遇句末标点（。！？；）或长停顿（>1.2s）→ 自动生成独立待办并继续监听；「、」不触发切分、尾句并入最后一条（已定，见 §14）。
- **AC-4（F2/R-X4）**：静音/空内容 → 不生成空待办。
- **AC-5（F2/R-E8）**：对拆分结果执行合并/拆分 → 列表更新且重启后保持。
- **AC-6（F2/R-X1）**：ASR 不可用/授权拒 → 弹文字兜底提示，文字记录仍可用。

### 12.2 提醒
- **AC-7（F3/R-E4,R-E5）**：设时间 T（默认 leadMinutes=10）→ T-10min 与 T 各收到通知（已定，见 §14）。
- **AC-8（F3/R-E6）**：到点未完成 → 每 10min 重复，最多 3 次（repeatCount 默认 3，可关闭；已定，见 §14）。
- **AC-9（F3/R-E7）**：标记完成 → 后续提醒取消。
- **AC-10（F3/R-X3）**：杀进程致通知未达 → 重开后在"错过的提醒"区可见该条标记"提醒未达"。
- **AC-11（F3）**：单条关闭重复（repeatCount=0）→ 仅保留提前（leadMinutes 默认 10，单条可调）+到点，不再重复（已定，见 §14）。

### 12.3 组织 / 完成 / 进度
- **AC-12（F4/R-O1）**：输入标签 → 出现已有标签联想；可跳过。
- **AC-13（F4）**：设分类/优先级 → 列表展示对应标识，可筛选。
- **AC-14（F5/R-S1）**：勾选完成 → 置底 + 完成态 + 进度 X+1。
- **AC-15（F5/R-U3）**：进度实时显示「完成 X / 共 Y」，Y 含进行中+已完成。
- **AC-16（F5）**：拖拽排序后顺序持久化。

### 12.4 持久化 / 异常
- **AC-17（F6/R-U1）**：杀进程/重启 → 当日列表（含完成态/顺序/分类/提醒）完整恢复。
- **AC-18（F6/R-U2）**：无网络 → 记录/查看/完成/编辑全部可用。
- **AC-19（F6/R-X2）**：本地存储损坏 → App 不崩溃、记录异常日志并提示数据可能受损，保留可操作内存态；v1 **不强制恢复**（轻量快照恢复为 v1.1，见 §14）。
- **AC-20（F-perm/R-S4）**：通过系统授权状态回调（iOS `authorizationStatus` / Android `areNotificationsEnabled`）检测到通知被禁 → 首页常驻"提醒可能不送达"提示，记录不受阻；无轮询（原"iOS 无法检测"表述已移除，改为依赖系统回调）。

### 12.5 权限
- **AC-21（F-perm/R-E9）**：未授权麦克风进语音 → 展示权限引导。
- **AC-22（F-perm）**：设置页可见权限状态并可跳转系统设置重新授权。

### 12.6 v1.1（仅验收口径，v1 不实现）
- **AC-23（F7，v1.1）**：可查历史日计划与完成率。
- **AC-24（F8，v1.1）**：周模板每日生成、单天可改、漏做可改时间补生成。
- **AC-25（F9，v1.1）**：可切换第三方 ASR。

### 12.7 P1 默认值收口（可测验收，对应 §13.2）

- **AC-26（F5/R-E10）取消完成**：勾选完成的待办执行「取消完成」→ 进度 X-1、该条移回进行中列表；若该条仍有未触发提醒，其提醒排程（提前/到点/重复）恢复并按原计划触发。
- **AC-27（F1/R-U4,R-U5）跨日/时区**：① 待办按创建自然日归属当日清单；② 设提醒 T 跨越自然日，到点仍在设定时刻触发并归入「当天进行中」展示；③ 切换设备时区后，已设绝对提醒时间不变（不漂移），仅展示随本地时区解释。
- **AC-28（F3/R-E11）提醒改期**：将提醒由 T 改为 T' → 旧触发点（含提前/重复）取消、仅 T' 生效，期间不发送重复通知（对应测试 TC-R3-06）。
- **AC-29（F1/R-X5）超长文本**：输入长度 ≥ 500 字 → 截断至 500 字并提示用户（对应测试 TC-T1-06）。
- **AC-30（F4/R-O1,R-O2）分类/标签**：① 未设分类默认「其他」；② 优先级默认「中」且不强制展示标识；③ 标签录入 "Work" / " work " / "Ｗｏｒｋ" 归一为同一标签（忽略大小写、首尾空格、全角半角）并去重；④ 筛选支持单维与组合。
