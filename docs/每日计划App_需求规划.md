## 一、背景与目标

**背景**：用户想要一款"能真正用起来"的每日计划工具。核心诉求是**极低门槛地记录当天待办**，录入覆盖**语音 + 文字**两种，降低"打开就要打字"的阻力。主流待办工具（滴答清单、Todoist、Microsoft To Do、Google Keep）功能完整但偏"管理"，对"只看今天、随手记"的轻量场景偏重。

**产品目标（v1）**
- 用户 **30 秒内**完成"今天要做什么"的记录（语音/文字均可）
- 关键待办能**准时提醒**，不漏事
- 用**分类/优先级/标签**做轻量组织，而非复杂项目管理

**业务目标**：以"轻量语音记录"为差异化切入，验证日活与次日留存（记录 → 提醒 → 完成闭环）。

## 二、目标用户与场景

| 维度 | 内容 |
|------|------|
| 目标用户 | 通用个人效率人群（不限定职场/学生） |
| 核心痛点 | 想记待办时手不方便打字；待办散落各处；到点忘记做 |
| 典型场景 | ① 通勤口述今日待办 ② 工作中随手打字加一条 ③ 到点弹提醒 ④ 睡前看完成度 |
| 平台形态 | **iOS + Android 原生 App**（v1 不做小程序/Web） |
| 数据存储 | **纯本地存储，无账号登录**（换机/卸载数据不保留，v1 简化） |

## 五、核心需求描述（EARS）

- **Ubiquitous**：系统应始终将用户当日待办持久化在本地存储，App 重启后完整恢复。
- **Event-driven**：当用户点击语音按钮并开始说话时，系统应持续监听并将语音实时转写为文字。
- **Event-driven**：当检测到停顿或标点时，系统应将已识别文本拆分为一条独立待办并加入当日列表。
- **Event-driven**：当用户为某条待办设定提醒时间到达时，系统应推送本地通知。
- **Event-driven**：当提醒时间到达且用户未标记完成时，系统应按设定间隔重复推送提醒，直至完成或关闭。
- **Unwanted**：若语音识别服务不可用或授权被拒，则系统应提示用户改用文字输入，并保持记录流程可用。
- **State-driven**：当待办被标记为完成后，系统应展示完成态并将其从进行中列表置底。
- **Optional**：当用户输入标签时，系统应支持从已有标签自动联想补全。

## 六、关键设计决策（已确认）

1. **语音方案**：v1 平台原生 ASR（免费/可离线），预留接口后续换第三方。
2. **语音交互**：持续听 + 自动拆分多条（按停顿/标点切分）。
3. **循环规则**：按周模板，可单独改某天；漏做项支持改到其他时间并补生成。
4. **上线范围**：核心优先，历史统计与循环待办后置 v1.1。
5. **完成进度**：v1 保留"今日完成 X / 共 Y"轻量进度。

### 已知项推荐默认值（待负责人确认）
- **提醒默认策略**：提前 10 分钟 + 到点提醒 + 每 10 分钟重复、最多 3 次；单条可调整或关闭重复。
- **分类/标签**：预设「工作 / 生活 / 学习 / 其他」+ 用户可自建分类；标签非必填、输入时联想补全。
- **权限与隐私**：首次启动引导麦克风/通知权限，附本地存储与无账号的隐私说明文案。
- **上架渠道**：iOS App Store（个人/企业开发者账号待定）、安卓主流商店（待定）——需负责人确认。

## 八、风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| 原生 ASR 中文/方言识别率有限 | 语音体验打折 | 文字兜底；v1.1 接第三方 |
| 自动拆分误切 | 一条变多条/多条变一条 | v1 支持手动合并/拆分 |
| 纯本地无同步，换机丢数据 | 留存受损 | 后续版本加账号云同步 |
| 系统通知受限（iOS 后台/勿扰） | 提醒漏达 | 明确免打扰策略 + 可靠性测试 |
