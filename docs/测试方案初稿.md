## 二、测试策略

### 2.1 总体策略
- **分层 + 双端一致性**：沿架构五层（UI / 领域 / 数据 / 语音 / 通知）做单元→集成→UI→端到端分层验证；业务规则（拆分、提醒计划计算、进度 X/Y、完成态流转）在**领域层单测**双端共用同一算法，规避「双端行为不一致」风险（架构风险项）。
- **可测性前置**：PRD 中量化阈值（停顿阈值、文本上限、重复次数）未定前，相关用例标注「期望值待确认」，不臆造判定标准。
- **异常优先（Graceful Degradation）**：单点失败（语音/通知/存储）必须不阻断核心记录流，作为 P0 回归重点。
- **本地零依赖**：所有用例在无网络 / 飞行模式下可独立通过（R-U2）。

### 2.2 测试方法
| 方法 | 用途 | 说明 |
|------|------|------|
| 单元测试 | 领域层规则（splitter、ReminderScheduler 触发点计算、X/Y 统计） | 双端共享逻辑，优先投入 |
| 集成测试 | Repository↔数据库、ASR↔领域层、通知层↔系统调度 | Mock 系统能力做确定性验证 |
| UI / 端到端 | 真实设备走完记录→提醒→完成闭环 | 真机 + 系统通知/ASR |
| 手动探索 | 语音真实识别率、拆分体验、30 秒记录目标 | ASR 依赖真人与环境音 |
| 专项（异常/兼容/性能） | 见第四~七章 | 独立 track |

### 2.3 测试环境
- 真机：iOS（最低版本待确认，架构用 iOS 13+）、Android（最低 API 待确认）。
- 模拟器：iOS Simulator / Android Emulator 用于基础功能，但**通知与真实 ASR 必须以真机为准**（模拟器 ASR、通知回调不完整）。
- 工具：XCTest / Espresso / 平台 UI 框架自带测试；埋点可用本地日志断言（不涉及上传）。

## 五、重点边界与异常场景（专项）

> 用户点名的 7 类重点，单列专项用例与可测性备注。

### 5.1 语音不可用（ASR 不可用 / 授权拒 / 离线无包）
- 用例见 TC-V2-05；扩展：iOS 离线未装中文离线包、Android 无 Google 服务环境、系统 ASR 崩溃。
- 可测性：需用 Mock ASR 注入 `unavailable/denied/offline` 三态（架构 §4.4 接口支持），真机仅验证降级路径。**判定标准**：文字记录流不中断即可，不需识别成功。

### 5.2 通知被禁 / 勿扰
- 用例见 TC-R3-08、TC-R3-09；扩展：iOS 专注模式、Android DnD（含 `bypassDnd` 授权与否两种）、低电量模式、Doze。
- 可测性：Android 可程序化切 DnD；**iOS 专注模式无法被 App 绕过且无法查询状态**，只能依赖用户授权「允许本 App 通知」+ App 内「待完成」列表兜底。需产品明确 iOS 提示触发条件（见 §9.10）。

### 5.3 存储损坏
- 用例见 TC-P6-03；扩展：DB 文件 0 字节 / 中间截断 / WAL 损坏 / schema 版本不匹配。
- 判定：不崩溃 + 不丢已有可恢复数据 + 不可恢复时明确提示（v1 实际策略见 §9.8）。

### 5.4 App 被杀重启
- 用例见 TC-P6-01、TC-R3-05、TC-R3-09；扩展：录音中杀进程（已识别未落库文本是否丢）、设提醒后杀进程（重启补偿是否重建排程）。
- 判定：所有已持久化数据完整恢复；内存态（未落库）允许丢失但不得崩溃。

### 5.5 空待办
- 用例见 TC-T1-02、TC-V2-03；扩展：语音静音、文字纯空格、合并后变空。

### 5.6 超长文本
- 用例见 TC-T1-06；**当前 PRD §12 验收标准完全缺失超长文本用例**，阈值与处理（截断/提示）均未定（见 §9.7）。

### 5.7 漏做补生成（v1.1 / F8）
- 用例见 TC-11-02；v1 不实现。需澄清：漏做检测时机（自动 23:59 还是手动进入）、补生成待办归属日、是否沿用原提醒时间（见 §9.17）。

## 九、PRD 验收标准不清晰 / 不可测 / 缺失清单（请产品澄清）

> 仅列问题，不补结论。括号内为对应 PRD 位置与影响。

1. **提醒默认策略未最终确认**（§13-1，影响 AC-7/8/11、TC-R3-01/02/04）：提前 10 分、重复每 10 分最多 3 次仍是「推荐默认值」，AC 已直接采用。需产品拍板最终值，否则用例期望值无法锁定。
2. **拆分规则量化缺失**（§5.2 R-E2、架构 §4.3，影响 AC-3、TC-V2-02）：停顿阈值（800ms~1.2s 为「如」）、拆分标点集合（，。！？；、是否全切？中文逗号/顿号切否？全角半角？）未定，AC-3「遇停顿/标点」无法精确断言。
3. **停止录音尾句处理二义**（§6.2，影响 TC-V2-06）：「并入最后一条 **或** 单独成条」为二选一，行为不确定，需明确。
4. **超长文本验收完全缺失**（§6.1 提「≥500字截断或提示待确认」但 §12 无 AC，影响 TC-T1-06）：PRD 验收标准未覆盖超长文本，且阈值/处理方式均未定。建议补 AC。
5. **存储损坏恢复策略与架构存在落差**（§5.4 R-X2 vs 架构 §3.1「v1 可仅记日志」）：AC-19 期望「尝试恢复或提示，留存可操作内存态」，架构说 v1 可能只记日志不恢复。需澄清 v1 实际是否做恢复；且「内存态」在杀进程后即丢失，与持久化目标（R-U1）冲突，需定义清楚。
6. **R-X3 与 R-S4 边界重叠且机制不清**（§5.3 R-S4、§5.4 R-X3，影响 AC-10/20）：「通知被禁/勿扰/离线」与「杀进程未达」归因不同（前者已调度被拦，后者未调度），补列逻辑应区分，PRD 混为一谈。需明确各自触发条件与首页呈现差异。
7. **iOS 通知被禁检测不可测**（§9 R-S4、AC-20、§7.1，影响 TC-PM-04）：iOS 无公开 API 查询用户是否关闭通知，App 无法程序化感知「通知被禁」。R-S4「常驻提示」在 iOS 上触发机制存疑，需架构/产品澄清（是否改为仅依赖用户主动关闭时的系统回调或引导文案）。
8. **拖拽排序作用域与交互未定**（§7.2、AC-16，影响 TC-D5-03）：已完成待办能否拖拽？拖拽是否跨「进行中/已完成」分组？排序与置底规则的交互需明确。
9. **取消完成/重做语义缺失**（US/F5，影响 TC-D5-06、TC-R3-07）：PRD 只定义「标记完成」，未定义「取消完成」。若支持，X/Y 如何回退、已取消的提醒是否恢复排程——均未定义。
10. **提醒改期场景无 AC**（影响 TC-R3-06）：用户修改提醒时间 T→T' 时，旧触发点取消、新触发点生效、无重复通知，PRD 验收未覆盖。
11. **分类/优先级默认值与筛选细节缺失**（§4.1 F4、AC-13，影响 TC-C4-03/04）：未设分类时默认「其他」如何展示？优先级默认「中」是否展示标识？筛选为单维还是组合？未定。
12. **标签联想来源与归一规则缺失**（R-O1、AC-12，影响 TC-C4-02/06）：联想来源是否含预设？标签重复/大小写/前后空格如何处理？未定义。
13. **无网络下语音入口行为冲突**（R-U2 vs 语音需联网，影响 TC-T1-04/TC-V2-05）：R-U2 称无网络记录可用（成立，文字兜底），但需明确「无网络 + 点语音」的预期是降级提示而非卡死，建议补一句明确。
14. **跨日 / 时区边界未定义**（§10 口径，影响 TC-R3/TC-P6）：23:59 新增待办在 00:01 是否仍属今天？提醒时间跨自然日如何归属？时区切换（出差）下提醒绝对时间是否漂移？需补边界。
15. **v1.1 循环待办（F8）细节空白**（§6.4、AC-24，影响 TC-11-02）：漏做检测时机（自动 23:59 或手动）、补生成待办归属哪天、是否沿用原提醒时间、与模板的覆盖关系——均未定义，v1.1 验收口径需细化。
16. **「30 秒记录」目标无验收锚点**（G1，§2.1）：为体验目标，建议明确是纳入手动体验验收还是仅埋点观测，避免被误读为自动化硬指标。
17. **埋点「触达率」跨平台判定差异**（§8.2、§11）：提醒触达以「系统回调」为准，iOS/Android 回调语义不同，目标值待确认，v1 不宜作为合格/不合格的硬性验收。
