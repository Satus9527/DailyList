## ② 严重/阻塞缺陷复盘与闭环确认

> 范围：按任务要求复盘 5 个已记录缺陷（M2-D1/D2、M3-D1/D2、M4-A）。所有修复均为**静态复验**（沙箱无 IDE，未运行 App）。其余非阻塞缺陷（M1 一般-1/2/3、M3 D3~D8、M4 B/C/D/E）在 §③/§④ 作为风险与 v1.1 候选项跟踪。

### 2.1 M2-D1 ｜ iOS 完成取消对高序号重复点不彻底（违反 AC-9）
- **根因**：iOS `ReminderScheduler.cancel` 硬编码 `repeatUpperBound = 3`，仅枚举 `__rep{1..3}`；而 UI `repeatOptions=[1,2,3,5]` 允许 `repeatCount=4/5`。任务完成后 `cancel` 残留 `__rep{4,5}` 仍触发，违反 AC-9/R-E7。
- **修复（#45）**：改为 `getPendingNotificationRequests` 按 `taskId` 前缀 `hasPrefix` 动态过滤后一次性 `removePendingNotificationRequests`，覆盖任意 `repeatCount`；`schedule` 先异步清旧再登记防竞态；UI 上限对齐 Android=5。
- **复验（静态）**：`ReminderScheduler.swift:172-178` 确认动态取消；`repeatUpperBound` 已无引用；模拟 `repeatCount=5` 时 `__rep{1..5}` 全移除（协调者复验通过）。
- **真机验证是否仍必要**：**是**。动态取消逻辑正确，但实际「完成即不再响」需真机用例 TC-R3-08（设 R=5→完成→确认无残留响铃）确认；并建议架构同步修订设计规格 §3.1 `REPEAT_MAX=3` 口径（M2 S1）。

### 2.2 M2-D2 ｜ Android 补偿重触发已过期提前点
- **根因**：Android `WorkManagerReminderScheduler.schedule` 缺少「跳过已过期点」守卫（对照 iOS `guard pt.fireAt > Date()`）。App 被杀后于 `now∈(T−L, T)` 重新打开触发 `rescheduleAllPending` 时，已过期的「提前点」以 `delay=0` 立即触发，产生重复/迟到提前提醒。
- **修复（#46）**：遍历触发点加守卫 `if (pt.fireAt.time <= now) continue`，过期点跳过不排 Work；`rescheduleAllPending` 复用同一 `schedule`。
- **复验（静态）**：`WorkManagerReminderScheduler.kt:60` 确认守卫存在；`now ∈ (T-lead, T)` 时仅排 T/重复点，跳过已过期 `T-lead`（协调者复验通过）。
- **真机验证是否仍必要**：**是**。需真机用例 TC-R3-05（杀进程→提前点之后/到点之前重开→确认提前点仅响一次、不迟到重发）。

### 2.3 M3-D1 ｜ Android `onEndOfSpeech`+`onResults` 双发 `onFinal`→重复落库（违反 AC-5/数据正确）
- **根因**：标准 `SpeechRecognizer` 在句末同时回调 `onEndOfSpeech` 与 `onResults`，二者均非空；`commitFinalSegment` 被调用两次→同一句话落两条待办。
- **修复（#65）**：新增 `emitFinal()` + `lastFinalTextInTurn` 去重窗口，`onEndOfSpeech`/`onResults`/长停顿/尾句四处 `onFinal` 统一走 `emitFinal`，同句仅提交一次；`beginListening` 重置窗口。
- **复验（静态）**：`NativeASRController.kt:48,88,116,127,154,202-218` 确认去重；模拟双发相同 final 仅 `add` 一次（协调者复验通过）。
- **真机验证是否仍必要**：**是**。去重依赖 OEM 行为，需在真机/模拟器用例验证连续句末、停顿、尾句各场景无重复条（M3 用例 8）。

### 2.4 M3-D2 ｜ iOS 缺失 Info.plist 致权限请求崩溃（阻塞运行）
- **根因**：仓库仅含源码、无 `.xcodeproj`/`.plist`，全仓无 `NSSpeechRecognitionUsageDescription`+`NSMicrophoneUsageDescription` 键；若 Xcode 工程未配置，运行请求语音/麦克风权限会**直接崩溃**。
- **修复（#66）**：新增 `DailyPlan/Info.plist`，含双权限键（简体中文文案）+ 最小宿主键；README 注明须挂 Xcode target。
- **复验（静态）**：`DailyPlan/Info.plist` 存在且含双权限键（plistlib 校验合法）。
- **真机验证是否仍必要**：**是（构建级+运行级）**。需确认：① Xcode target 已挂载该 plist；② `asr_split_config.json` 已加入 Build Phases「Copy Bundle Resources」（仓库无 `.xcodeproj` 无法静态确认，M3 §3.1）；③ 真机/模拟器首次请求权限不崩。此项为 **iOS 上线的硬前置**。

### 2.5 M4-A ｜ Android 跨 0 点任务在创建日也展示（违反 AC-27②/规格 §3.1）
- **根因**：`TodayViewModel.reload` 对 `tasksByDisplayDay(today)` 结果未施加 `displayDay==today` 末过滤（对照 iOS `reload` 的 `tasks.filter { $0.displayDay == today }` 及规格 §3.3 伪代码）。`tasksByDisplayDay` 查询含 `date = :day` 子句，把跨 0 点任务**创建日也纳入**，导致该任务在创建日与触发日重复出现（进度 Y 口径双计）。
- **修复（#77）**：`TaskDao.tasksByDisplayDay` 谓词改为双分支——普通任务（`date=:day 且非跨0点`）归创建日、跨0点任务（`remind_at 所属日≠date 且 =:day`）仅归触发日，不再用 `OR date=:day` 把跨0点任务也纳入创建日。
- **复验（静态）**：`TaskDao.kt:71-81` 确认谓词；模拟 `date=今天/remindAt=明天 08:00` 仅现于明天、`date=今天/remindAt=今天 20:00` 正常在今日（协调者复验通过）。
- **真机验证是否仍必要**：**是**。需真机用例验证「7/24 设 7/25 07:30 提醒→7/24 当日列表不含该条、7/25 出现于进行中」；并回归进度 Y 不双计。

### 2.6 其余已记录非阻塞缺陷（状态留痕）
- **M1 一般-1/2/3**：Android 重建后种子纳入捕获链、iOS 日志事件与提示对齐、AC-17/19 端到端未经真机——均进入 §③ 风险项与真机清单。
- **M3 D3/D4/D5/D6/D7/D8**：语音超长截断无提示、iOS AudioSession 打断、Core Data 跨线程、合并/拆分 UI（已由 M4 补齐）、埋点标注、权限深链——D6 已由 M4 解决，其余进 §③ 风险/§④ v1.1 候选。
- **M4 B/C/D/E**：合并邻接规则双端不一致、合并/拆分入口范围双端差异、iOS 错过区跳转简化、iOS 麦克风权限状态刷新时机——均建议级，进 §③/§④。

> **闭环判定**：5 个严重/阻塞缺陷（M2-D1/D2、M3-D1/D2、M4-A）**代码已修复且静态复验通过**，但**修复有效性仍需真机运行确认**（尤其是 iOS Info.plist 挂载、Android 过期点守卫、重复落库去重）。
