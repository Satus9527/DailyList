## 二、需要注意的问题（风险与约束，知晓即可）

| 类型 | 内容 | 应对 |
|------|------|------|
| 环境约束 | TAPD / GitHub / 腾讯文档连接器**未连通** | 事项用本环境任务列表代替；真实流转需先连通连接器 |
| 系统通知 | iOS 专注 / Android DnD / Doze / 被杀 → 提醒漏达不可避免 | PRD 文案 + App 内「错过的提醒」兜底；触达率指标 v1 不宜硬验收 |
| 双端漂移 | 拆分阈值/标点集 Swift/Kotlin 各写一遍易不一致 | 集中在共享配置/规格文档/KMM 共享模块，从第一天参数化 |
| 无同步 | 纯本地零登录 → 换机丢数据 | v1.1 加账号云同步（已预留 `syncState` 扩展点） |
| 范围蔓延 | v1 功能易膨胀 | 守核心（记录/语音/提醒/分类/完成），v1.1 不露 UI 仅预留 |
| 实现顺序 | 建议：数据层/F1/F5/F6 → 权限+F3 提醒 → F2 语音（最高风险放后）→ F4 可平行 | 见研发可行性评审 §5.1 |

## 三、流转建议（项目角色）
- P0 四项请对应负责人/你本人**在研发启动前拍板**，结论回填 PRD 与架构文档对应章节。

- 将 P0/P1 待办拆为事项，分配开发/测试并添加关注人（受连接器限制，先落本环境任务列表）。
- 排期、上架账号、资源类决策请找对应负责人确认，文档中不臆断。
