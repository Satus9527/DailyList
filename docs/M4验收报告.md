## ③ D3 / D4 / S5 / R-4 专项核对

### 3.1 D3（错过提醒区）专项
- **派生条件一致性**：双端均 `remindAt<now && !isDone && displayDay==today`。iOS在 `missedTasks`+`reload` 双重保证；Android在 `tasksByDisplayDay` 查询 + 内存 `filter` 保证（`:110`）。✅
- **与 M2 `tasksWithPendingReminders` 互补、不新增触发日志表**：M2 为「未来待响」（`LocalTaskRepository.swift:32-45` / `TaskDao.kt:60-68`），M4 为「已过期待响未完」，二者并集构成兜底；全仓 `grep` 无 `Reminder.fired`/`TriggerLog` 等新表/字段。✅ 数据层零返工。
- **标记「提醒未达」+ 点按跳转/完成**：双端胶囊文案固定「提醒未达」、橙红/白字、带无障碍标签；勾选即完成并移出、点按打开提醒设置面板。✅（iOS 跨日项仅弹提醒面板，未实现「切到展示日视图」，见缺陷 J，建议级）。

### 3.2 D4（首页常驻提示）专项
- **检测机制**：iOS 仅通知权限（`.provisional/.ephemeral` 视为可能不达，符合 §2.1）；Android 通知权限 + DND（`INTERRUPTION_FILTER_NONE/ALARMS/PRIORITY` 且未授权绕过，API≥23）。✅
- **UI 横幅**：iOS `Banner`（橙底胶囊，常驻，点按深链，`TodayView.swift:98-117`）；Android `NotificationBannerBar`（`#FFF3CD` 常驻 Surface，非自动消失，符合 §2.2「常驻态」，`TodayScreen.kt:358-383`）。注：任务提示「Android Snackbar」，但实际用常驻 `Surface` 更贴合「非自动消失」要求，可接受。✅
- **深链**：双端按风险类型分别跳对应系统设置页。✅

### 3.3 S5（跨日归类）专项
- **`displayDay` 算法**：iOS `TaskDTO.displayDay`（`TaskDTO.swift:57-63`）、Android `displayDay(task)`（`Task.kt:79-83`）均实现「跨 0 点取 `remindAt` 所属本地日，否则取 `date`」，设备本地时区（`TimeZone.current` / `TimeZone.getDefault()`）。✅ 算法一致。
- **取数（展示日）**：iOS `tasksForDisplayDay`（`LocalTaskRepository.swift:49-70`）、Android `tasksByDisplayDay`（`TaskDao.kt:72-80`）谓词语义一致（`date=:day OR (remindAt 本地日=:day 且 ≠ date)`）。✅
- **不改动 `date` 存储**：双端仅读查询，合并/拆分均未回写 `displayDay` 派生值（iOS合并取主条 `date`；Android合并取 `earliestDate`），`date` 字段不受 S5 影响。✅
- **⚠️ 关键偏差（缺陷 A）**：Android ViewModel 未对 `all` 施加 `displayDay==today` 末过滤（对照 iOS `reload` 的 `tasks.filter { $0.displayDay == today }` 及规格 §3.3 `buildTodaySections` 伪代码），导致跨 0 点任务在创建日也被纳入「进行中」，与 §3.1 示例「7/24 当日列表不含它」冲突。iOS 行为符合规格。

### 3.4 R-4（设置页 + 合并/拆分）专项
- **设置页**：双端均含通知/麦克风权限状态 + 深链 + 语音开关（持久化）+ P0-1 隐私文案 + 默认提醒策略只读；入口均为首页齿轮。✅ 完全覆盖 §4.1。
- **合并/拆分 UI**：双端长按 → 菜单/弹窗 → 调用 M3 `TaskMergeSplitUseCase`，即时更新 + 持久化（AC-5）。✅
- **⚠️ 细节偏差**：
  - **缺陷 B**：「上一条」邻接规则双端不一致。iOS 限 `inProgressTasks[idx-1]`（`TodayTaskViewModel.swift:269-273`）；Android 用平铺 `flat`（missed+inProgress+done）前一个（`TodayScreen.kt:184-186`），可能把「错过的提醒」或「已完成」条当作上一条合并。建议对齐为「同展示日、相邻前序」（规格 §4.2）。
  - **缺陷 C**：iOS 仅在「进行中」区块挂 `onMergeUp/onSplit`（错过的提醒、已完成区块未传，见 `TodayView.swift:124-144,167-179`），即跨日/已完成条无法长按合并拆分；Android 三区块均挂。建议双端统一（或产品确认仅进行中可操作）。

### 3.5 R-3 口径专项
- 实现采用「尾句单独成条」（`VoiceTaskSplitter` 双端，见 ②AC-3 证据），与 `设计规格_M4增强.md §5` 裁定一致。PRD `R-E2`/`AC-3` 字面仍为「并入最后一条」，需产品按 §5 回写（见⑥）。✅ 代码无需改。
