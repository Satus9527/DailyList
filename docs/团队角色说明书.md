# 每日计划 App · 团队角色说明书

> 本文档定义项目「项目 / 产品 / 开发 / 测试 / 架构」5 个角色的职责、交付物与协作机制（RACI）。
> 主 agent 作为**项目协调中枢 + 产品主线**，负责建团队、分任务、汇总与流转。
> 环境约束：TAPD / GitHub / 腾讯文档连接器当前未连通，事项用本环境任务列表代替，文档统一落 `/workspace`。

---

## 一、角色定义

| 角色 | 定位 | 核心职责 | 主要交付物 |
|------|------|---------|-----------|
| **项目 PM** | 统筹与推进 | 排期、风险跟踪、跨角色协调、里程碑、决策升级、确保交付物流转 | 项目计划、进度/风险周报、里程碑清单 |
| **产品 Product** | 需求 owner | 需求规划、PRD 撰写、用户故事、验收标准、优先级、评审组织 | 需求池、PRD、验收标准 |
| **架构 Arch** | 技术决策 | 技术选型、数据模型、本地存储、语音 ASR 集成、通知/提醒架构、模块与接口、风险 | 技术架构文档、数据模型、接口定义 |
| **开发 Dev** | 实现 | 按 PRD+架构编码、自测、提代码；当前先做脚手架/技术预研 | 可运行 App、代码、自测报告 |
| **测试 QA** | 质量 | 基于 PRD 写用例、边界/异常场景、回归范围、Bug 描述、验收清单、质量总结 | 测试用例、验收清单、Bug 报告 |

## 二、RACI 矩阵

| 阶段 / 事项 | 项目 | 产品 | 架构 | 开发 | 测试 |
|------------|------|------|------|------|------|
| 需求规划 | A | R | C | C | C |
| PRD 撰写 | A | R | C | C | C |
| 技术方案/架构 | A | C | R | C | I |
| 研发实现 | A | C | C | R | I |
| 测试用例/验收 | A | C | I | C | R |
| 上线复盘 | R | C | C | C | C |

R=负责执行　A=问责/统筹　C=被咨询　I=知会

---

## 三、协作与流转规则

1. 每个阶段产出文档 → 保存到 `/workspace`（项目资料库）→ 创建任务分配给下一角色并添加关注人。
2. 角色间通过共享任务列表与本对话协调；主 agent 负责收口与评审组织。
3. 涉及排期、资源、上线范围、账号/上架等决策，由对应角色提醒找负责人确认，不在文档中臆断。
4. 开发/测试在 PRD 与架构评审通过前不进入重实现，先提供可落地性反馈。

## 五、已确认的关键决策（供各角色引用）

- 平台：iOS + Android 原生；存储：纯本地、零登录
- 语音：v1 平台原生 ASR，持续听 + 按停顿/标点自动拆分多条
- 提醒：提前 10 分钟 + 到点 + 每 10 分钟重复最多 3 次（单条可调）
- 循环：按周模板，可单独改某天；漏做项支持改到其他时间并补生成
- 进度：v1 显示「今日完成 X / 共 Y」
- 范围：核心优先（记录/语音/提醒/分类标签/完成编辑），历史统计与循环待办后置 v1.1
