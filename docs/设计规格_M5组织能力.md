### 2.4 任务↔标签关联的领域模型读取扩展（**M5 新增，复用 M1 关联表**）

为支持 F4 编辑/展示与按标签筛选，需把「某任务的标签集」暴露到领域层。M1 已有 `TaskTagCrossRef`，但 `TaskDTO`/`Task` 领域模型当前**不含**标签列表。本 M5 新增**只读/只写扩展方法**（不新增表、不新增列）：

- 读取：`tags(forTaskId:)` / `tagIds(forTaskId:)` —— 经 `TaskTagCrossRef` 联表返回该任务标签。
- 写入：`setTags(taskId: Set<UUID>)` —— **整体替换**该任务的标签关联（先删旧 `task_tag` 行，再按归一后的 `Tag.id` 批量插入）；与 `TaskRepository.update` 解耦，由编辑页在保存时调用。

> 标记：**新增**。但底层完全复用 M1 `TaskTagCrossRef` 表与级联删除约定；不改动 `Task` 表结构。

## 3. Repository / DAO 筛选方法

> 在 M1 §5 的 7 方法（iOS）/ 8 方法（含 M4 `tasksForDisplayDay`）之外，**新增筛选相关方法**。所有方法主线程外执行（iOS `throws` + `@MainActor` 桥接刷新；Android `suspend`）。筛选作用于「某展示日」任务集，与 M4 §3 展示日口径一致（默认当日）。

### 3.1 筛选条件值类型（双端一致）

```swift
// Swift
struct TaskFilter: Equatable {
    var categoryId: UUID? = nil        // nil = 不限分类
    var priority: Priority? = nil      // nil = 不限优先级
    var tagIds: Set<UUID> = []         // 空 = 不限标签；非空 = 任务须同时拥有全部这些标签（AND）
    var untaggedOnly: Bool = false     // true = 仅返回「无任何标签」的任务（与 tagIds 互斥，优先于 tagIds）

    /// 空条件 = 全部（§6）
    var isEmpty: Bool {
        categoryId == nil && priority == nil && tagIds.isEmpty && !untaggedOnly
    }
}
```

```kotlin
// Kotlin
data class TaskFilter(
    val categoryId: UUID? = null,      // null = 不限分类
    val priority: Priority? = null,    // null = 不限优先级
    val tagIds: Set<UUID> = emptySet(),// 空 = 不限标签；AND 语义
    val untaggedOnly: Boolean = false  // true = 仅无标签任务
) {
    val isEmpty: Boolean
        get() = categoryId == null && priority == null && tagIds.isEmpty() && !untaggedOnly
}
```

### 3.3 SQL / Core Data 谓词示意

**组合筛选（Android Room，以 `date == :day` 为基础；NULL 哨兵表示「不限」）：**

```sql
SELECT t.* FROM task t
WHERE t.date = :day
  AND (:cat IS NULL OR t.category_id = :cat
       OR (:cat = :otherId AND t.category_id IS NULL))   -- 筛「其他」含未归类项（§6）
  AND (:prio IS NULL OR t.priority = :prio)
  AND (:untagged = 1 OR :tagCount = 0
       OR (:untagged = 0 AND t.id IN (
            SELECT task_id FROM task_tag
            WHERE tag_id IN (:tagIds)
            GROUP BY task_id
            HAVING COUNT(DISTINCT tag_id) = :tagCount       -- AND 语义：须同时拥有全部指定标签
       )))
ORDER BY t.is_done ASC, t.sort_order ASC;
```

**组合筛选（iOS Core Data 谓词示意）：**

```swift
var sub = [NSPredicate]()
sub.append(NSPredicate(format: "date == %@", day))
if let cat = filter.categoryId {
    // 筛「其他」含 nil（§6）
    if cat == CategorySeed.otherId {
        sub.append(NSPredicate(format: "categoryId == %@ OR categoryId == nil", cat as NSUUID))
    } else {
        sub.append(NSPredicate(format: "categoryId == %@", cat as NSUUID))
    }
}
if let p = filter.priority { sub.append(NSPredicate(format: "priority == %@", p.rawValue)) }
if filter.untaggedOnly {
    sub.append(NSPredicate(format: "tags.@count == 0"))
} else if !filter.tagIds.isEmpty {
    // AND：任务须包含全部指定 tag id
    sub.append(NSPredicate(format: "SUBQUERY(tags, $t, $t.id IN %@).@count == %d",
                            filter.tagIds.map { $0 as NSUUID }, filter.tagIds.count))
}
let predicate = NSCompoundPredicate(andPredicateWithSubpredicates: sub)
```

> 跨 0 点任务（M4 §3）的纳入：DB 层 `filteredTasks` 以 `date == :day` 为主；若需与 M4 展示日完全一致，可在 ViewModel 层对 `tasksByDisplayDay(day)` 的结果套用内存版 `TaskFilter.matches(_:)`（见 §3.4）。两种路径结果一致，DB 路径用于性能/单测，内存路径用于与首页三区块（错过的提醒/进行中/已完成）天然一致。**推荐 ViewModel 采用内存过滤**（复用 M4 已加载的展示日集合，零额外查询）。

### 3.4 内存版筛选谓词（ViewModel 推荐主路径）

为与 M4 首页三区块一致，定义平台无关 `matches`：

```
FUNCTION matches(task, filter) -> Bool:
    IF filter.categoryId != nil:
        cat = (task.categoryId ?? OTHER_ID)          // 未归类视为「其他」（§6）
        IF cat != filter.categoryId: RETURN false
    IF filter.priority != nil AND task.priority != filter.priority: RETURN false
    IF filter.untaggedOnly:
        IF task.tags(或 tagIds).isNotEmpty: RETURN false
    ELSE IF !filter.tagIds.isEmpty:
        IF NOT filter.tagIds ⊆ task.tagIds: RETURN false   // AND 语义
    RETURN true
```

> 仅给出视图结构、状态流与 ViewModel 方法签名（可编译级），不写完整实现。UI 复用 M4 首页三区块框架，F4 仅新增「编辑页分类/优先级/标签」与「首页筛选栏」，与 M4 D3/D4/S5 不冲突（§4.3）。

### 4.1 任务创建 / 编辑页（F4 输入）

编辑页以 M4 `ReminderSettingView`（iOS）/ `ReminderSettingSheet`（Android）为基底**扩展**（不另起新页）：在同一 sheet 内增加「分类 / 优先级 / 标签」三段，与既有提醒设置共存。

**分类选择器**
- 展示 4 个预设 + 用户自建列表（来自 `CategoryRepository.all()`）。
- 选中即设 `categoryId`；提供「+ 新建分类」入口 → 调 `CategoryRepository.add(name:)`（自建 `isPreset=false`）。
- 默认值：当前任务 `categoryId` 或「其他」（`...0004`）。

**优先级选择器**
- 三选一：高 / 中 / 低，默认「中」。
- 选中即设 `priority`；列表行**不强制展示优先级标识**（§6，AC-30②），仅编辑页可选；若展示，用极小灰度文字/圆点，不喧宾夺主。

**标签输入框**
- 自由输入，输入时实时调 `suggestTags(prefix:limit:)` 联想补全（下拉候选点击即填）。
- 确认方式：回车 或 输入 `,`/`，` → 将当前词**归一后**作为一个标签加入 chips；重复（归一后相同）自动去重。
- 每个已加标签为可删 chip（× 移除）。
- 保存时：对每个标签调 `TagRepository.addOrReuse(normalizedName:)` 得到 `Tag.id`，收集为 `Set<UUID>`，再调 `TaskRepository.setTags(taskId:tagIds:)` 整体替换。
- 非必填、可跳过（AC-12，§6）：清空即无标签。

## 5. 归一 / 去重算法规格（对应 AC-30③ / R-O1）

### 5.1 归一函数签名（双端，复用 M1 已实现 `TagNormalizer`）

```swift
// iOS（M1 已落地 TagRepository.swift 内的 TagNormalizer，本 M5 确认口径）
enum TagNormalizer {
    static func normalize(_ raw: String) -> String {
        let trimmed = raw.trimmingCharacters(in: .whitespacesAndNewlines)      // 去首尾空格/换行
        let halfWidth = trimmed.applyingTransform(.fullwidthToHalfwidth, reverse: false) ?? trimmed  // 全角→半角
        return halfWidth.lowercased()                                          // 忽略大小写
    }
}
```

```kotlin
// Android（M1 已落地 TagRepository.kt 内的 TagNormalizer，本 M5 确认口径）
object TagNormalizer {
    fun normalize(raw: String): String {
        val trimmed = raw.trim()                                  // 去首尾空格（建议补 trim('\n') 等价）
        val halfWidth = trimmed.fullWidthToHalfWidth()           // 全角→半角
        return halfWidth.lowercase()                              // 忽略大小写
    }
    private fun String.fullWidthToHalfWidth(): String =
        map { c ->
            when {
                c == '　' -> ' '                                  // 全角空格 U+3000 → 半角空格（补全项）
                c.code in 0xFF01..0xFF5E -> (c.code - 0xFEE0).toChar()  // 全角标点/字母/数字
                else -> c
            }
        }.joinToString("")
}
```

> **Android 补全建议**：M1 Android `TagNormalizer` 仅映射 `0xFF01..0xFF5E`，未显式处理全角空格 `U+3000`。为与 iOS `.fullwidthToHalfwidth` 完全等价（iOS 会同时归一 U+3000），建议在 M5 实现时于 `fullWidthToHalfWidth` 增加 `c == '　' -> ' '` 分支（见上式），保证双端一致。此改动仅增强归一完整性，不影响既有已存归一值。

### 5.2 全角→半角映射表要点

| 全角字符范围 | Unicode | 转换 | 半角结果 |
|-------------|---------|------|---------|
| 全角空格 | `U+3000` | 直接映射 | `U+0020`（半角空格） |
| 全角标点/数字/字母 | `U+FF01`–`U+FF5E` | `code - 0xFEE0` | `!`–`~`（含 `０-９`、`Ａ-Ｚ`、`ａ-ｚ`、全角标点） |
| 其他字符 | — | 保持不变 | 原字符 |

- 归一**顺序固定**：① 去首尾空格/换行 → ② 全角转半角 → ③ 小写。
- 归一结果用于**写入（Tag.name）与查询（前缀/相等比较）**，保证「同一视觉标签」在库中唯一。

### 5.3 AC-30③ 验证：`Work` / ` work ` / `Ｗｏｒｋ` 归一为同一标签

| 输入 | ① 去首尾空格 | ② 全角→半角 | ③ 小写 | 归一结果 |
|------|------------|------------|--------|---------|
| `Work` | `Work` | `Work` | `work` | `work` |
| ` work ` | `work` | `work` | `work` | `work` |
| `Ｗｏｒｋ` | `Ｗｏｒｋ` | `Work` | `work` | `work` |

- 三者归一后均为 `work`，`TagRepository.addOrReuse(normalizedName:"work")` 命中同一 `Tag` 行 → 写入 `TaskTagCrossRef` 指向同一 `tagId` → 天然去重。
- 联想补全时输入前缀也先经 `normalize` 再 `BEGINSWITH`/`LIKE`，故输入 `wo`/`ＷＯ` 均能命中所存 `work`。

## 6. 边界与默认值（对齐 §10 / AC-30 / R-O2）

| 边界 / 默认值 | 规则 | 对应条目 |
|--------------|------|---------|
| 未设分类 | 默认归「其他」预设（`...0004`）；`categoryId == nil` 在逻辑上等同「其他」，筛选「其他」须含 nil（§3.3） | AC-30①、R-O2、§10 |
| 优先级默认 | 默认「中」(`medium`)；**不强制展示标识**（列表行可不显示；编辑页可选） | AC-30②、R-O2 |
| 标签非必填 | 可跳过、可清空；无标签任务仍可正常保存/筛选（可经 `untaggedOnly` 筛选） | AC-12、R-O1 |
| 筛选空条件 | `TaskFilter.isEmpty == true` → 返回当日全部任务（= 不过滤） | AC-30④、R-O2 |
| 组合筛选语义 | 分类+优先级+标签 任意组合，**AND** 语义；多标签间亦 AND（任务须同时拥有全部） | AC-30④、R-O2 |
| 标签写入归一 | 任何标签写入/查询前必经 `TagNormalizer.normalize`（§5） | AC-30③、R-O1 |
| 预设分类保护 | 「工作/生活/学习/其他」`isPreset=true`，不可删/改名；自建可删，删除回退「其他」 | M1 §3.2 |
| 删除任务 | 级联删 `TaskTagCrossRef` 关联行（`ON DELETE CASCADE`），标签行本身保留（可能被其他任务复用） | M1 §4.2 |
