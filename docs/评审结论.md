## 二、关键决策回顾

### 2.1 P0 四项（已拍板并回填 PRD §14 / 架构 §十一）

| 编号 | 阻塞项 | 方案 | 最终值 / 口径 |
|------|--------|------|--------------|
| P0-1 | 语音 ASR 策略 | **C（允许联网识别）** | ASR 优先设备端识别，设备端不可用时联网回退；音频可能发往系统厂商（Apple/Google）识别服务，**非本 App 自有服务器、不附带账号与待办写回**；重写隐私文案（PRD §9），去掉"纯本地零网络/不上传账号"绝对表述；用户可在设置关闭语音输入。 |
| P0-2 | 提醒默认策略 | **A（默认推荐值 + 单条可调）** | 默认 `leadMinutes = 10`（T-10 提前）、`repeatCount = 3`（每 10 分钟重复最多 3 次，0 表示关闭）；每条 Task 可独立覆盖两字段；AC-7/8/11 期望值锁定。 |
| P0-3 | 存储损坏兜底 | **v1 选 B；v1.1 升级 C** | v1（方案 B）：损坏时**仅不崩溃 + 记日志，不强制恢复**（零网络无备份源）；v1.1（方案 C）：引入每日本地轻量快照回滚。R-X2 / AC-19 口径已同步。 |
| P0-4 | 语音拆分规则 | **C（温和）** | 拆分信号 = 句末标点 `{。！？；}` 为主 + 长停顿 `>1.2s` 为辅；**不含「、」与换行**（顿号/换行视为同一待办内并列内容）；尾句并入最后一条（无条则单独成条）；阈值/标点集双端共享配置。R-E2 / AC-3 已量化。 |

### 2.2 数据模型变更（支撑 P0-2 与重启补偿）
- **新增字段 `Task.leadMinutes`（Int，默认 10）**：提前提醒分钟数，`>0` 时生成"提前"触发点；单条可覆盖。
- **新增字段 `Task.repeatCount`（Int，默认 3）**：到点未完成重复次数，`0` 表示不重复/关闭重复；单条可覆盖。
- **新增接口 `TaskRepository.tasksWithPendingReminders(until:)`**（即原缺口 B）：返回未完成且含未触发提醒、触发点在 `[now, until]` 区间内的待办（含跨日场景），支撑 App 启动/重启补偿重排未来提醒。
- 触发点 `Reminder` 由 `leadMinutes` / `repeatCount` 推导生成（架构 §6.2）；同步扩展点 `updatedAt` / `syncState` / `id(UUID)` 维持不变，为 v1.1 云同步留路。

## 四、关键依赖

| 依赖 | 用途 | 成熟/风险 | 说明 |
|------|------|----------|------|
| **原生 ASR** | F2 语音输入（iOS `Speech` / `SFSpeechRecognizer`，Android `android.speech.SpeechRecognizer`） | 中风险 | iOS on-device 需预装中文离线包，否则回退联网；Android 多默认联网、依赖 GMS，无 GMS 设备（部分国产 ROM/华为）F2 可能整体退文字（R-X1）。可用性非 Guaranteed。 |
| **本地通知** | F3 提醒（iOS `UNUserNotificationCenter`，Android `WorkManager` + `NotificationManager`） | 成熟 | iOS 系统持有 pending、被杀仍触发；Android 用 WorkManager 规避 Doze，需重启补偿。选型正确。 |
| **本地存储** | F6 持久化（iOS Core Data / GRDB，Android Room） | 成熟 | 官方 SQLite 封装，事务/迁移/结构化查询齐备，单日数据量极小，非风险点。 |

### 4.1 iOS / Android 差异点（需研发与测试重点关注）
- **ASR**：iOS on-device 需预装离线包；Android 默认联网 + 依赖 GMS，无 GMS 设备可能整体不可用。
- **通知调度**：iOS 一次性预排 T-10/T/T+10/T+20/T+30，完成即批量取消；Android 各触发点起独立 Work，触发时**实时查完成态**。行为等价，但"完成态判定时机"不同，需统一验收口径（完成即不再响）。
- **DND / 专注拦截**：iOS **无法绕过**系统专注模式，只能文案引导 + App 内「待完成」列表兜底；Android 可 `setBypassDnd(true)`，但需 `ACCESS_NOTIFICATION_POLICY` 用户授权。
- **领域逻辑双实现**：Swift / Kotlin 两套代码，存在漂移风险 → 阈值/标点集必须集中在双端共享配置，从第一天参数化（规避"双端行为不一致"）。

## 五、风险点与缓解措施

| 风险点 | 影响 | 等级 | 缓解措施 |
|--------|------|------|----------|
| **系统通知漏达**（iOS 专注 / Android DnD / Doze / 被杀） | 提醒漏事 | 高 | ① PRD 文案引导用户在专注模式允许本 App 通知；② App 内「错过的提醒」区兜底（R-X3 / R-S4）；③ 可靠性专项测试覆盖（杀进程/Doze/低电量/勿扰，TC-R3-05/08/09）；④ 触达率 v1 不作为硬验收（仅埋点观测）。 |
| **双端拆分漂移**（同一算法两语言各写易不一致） | 体验割裂、验收争议 | 中 | ① 拆分标点集 `{。！？；}` 与停顿阈值 `>1.2s` 集中在双端共享配置（.json / 代码生成 / 复制常量，待研发定形态）；② 领域层 splitter 单测双端共用同一算法；③ 测试双端一致性核对（拆分结果、进度口径）。 |
| **纯本地无同步**（换机/卸载丢数据） | 留存受损 | 中 | ① v1 明确接受该代价，专注跑通"记录→提醒→完成"闭环；② 已预留 `updatedAt` / `syncState` / `id(UUID)` 扩展点，v1.1 加账号云同步（架构 §九）。 |
| **范围蔓延**（v1 功能膨胀） | 排期/复杂度失控 | 中 | ① 严格守核心（记录/语音/提醒/分类/完成），防蔓延声明（PRD §0 / §4.3）；② v1.1 不露 UI、仅预留扩展点；③ 所有同步能力仅留扩展点，v1 不实现、不预留入口。 |
| 原生 ASR 识别率有限（中文/方言） | 语音体验打折 | 高 | 文字兜底（F1）+ 识别后编辑 + 手动合并/拆分（AC-5）；v1.1 接第三方（F9）。 |

## 七、研发启动建议

### 7.1 实现顺序（与架构 §10、研发评审 §5.1 一致）
> **数据层 / F1 / F5 / F6 → 权限 F-perm + F3 提醒（含重启补偿）→ F2 语音（最高风险放后）→ F4 可平行推进**

- **阶段①**：双端骨架 + 数据层（Task/Category/Tag + Repository，含 `leadMinutes`/`repeatCount`/`tasksWithPendingReminders`）+ F1 文字新增 + F5 完成/编辑/删除/拖拽 + F6 持久化。零外部依赖、风险最低，先跑通"记录→完成"主闭环，验证 X/Y 进度。
- **阶段②**：F-perm 权限引导（麦克风/通知）+ F3 提醒（含重启补偿 `rescheduleAllPending`）。提醒是核心差异点、跨平台差异大，宜早暴露；权限是 F2/F3 的准入前提。
- **阶段③**：F2 语音输入（持续听 + 自动拆分 + 联网/授权失败降级）。最高风险（ASR 离线/GMS/误切），放最后攻坚，避免阻塞基础闭环。
- **阶段④**：F4 分类/优先级/标签（P1）。与核心闭环解耦，可平行推进；P1 须随 v1 上线。

### 7.2 里程碑划分
| 里程碑 | 范围 | 出口标准（建议） |
|--------|------|----------------|
| **M1 基础闭环** | 数据层 + F1 + F5 + F6 | 「记录→完成」主闭环跑通，X/Y 进度正确，重启/杀进程数据完整恢复（AC-1/14/15/16/17/18） |
| **M2 提醒与权限** | F-perm + F3（+重启补偿） | 提前+到点+重复提醒正确；完成取消后续；杀进程/重启补偿重排未来提醒；通知被禁常驻提示（AC-7~11/20~22） |
| **M3 语音输入** | F2（含降级兜底） | 实时转写、温和拆分、静音不生成空待办、不可用退文字、合并/拆分纠正持久化（AC-2~6） |
| **M4 组织能力** | F4（P1，可平行） | 分类/优先级/标签预设与自建、联想补全、去重归一、单维/组合筛选（AC-12/13/30） |
| **M5 集成与验收** | 双端一致性 + 专项 + 灰度准备 | 全量 AC 回归通过；语音降级/通知可靠性/存储损坏专项报告；双端一致性核对；埋点就绪 |

> **建议第一个研发里程碑 = M1（数据层 / F1 / F5 / F6）**：零外部依赖、风险最低，先验证核心"记录→完成"闭环与本地持久化，为后续提醒/语音提供稳定地基。
